# M8: vehicle pipeline (wasm sim, worker loop, snapshots, interpolation)

Goal: the browser runs the full simulation in the worker and shows moving vehicles on the map.
- Snapshots cross the boundary as transferable, double-buffered typed arrays.
- The main thread interpolates them at display rate and draws them with a `ParticleContainer`.
- Speed controls work, and stats arrive at 1 Hz.
- A committed check proves the wasm build produces the same state hashes as native Rust.

Follow `docs/plan.md` §3.2 and the CLAUDE.md boundary rules.

## `trapiks-sim-core`

- **`src/fixtures/scenarios.rs`:** the deterministic scenarios move here from the tests, so native and wasm run identical code.
  - `pub fn four_way_5000() -> u64` returns the state hash of the M5 schedule, as updated in M6 and M7b.
  - `pub fn grid_city_demand_1000() -> u64`: `grid_city(20×20 @ 150)`, `SimConfig { seed: 5, mode: City, vehicles_per_hour: 8000 }`, 1,000 ticks, returning the hash.
  - `pub const FOUR_WAY_HASH_5000: u64` and `pub const GRID_CITY_HASH_1000: u64`.
- Native tests assert that each function equals its constant.
- `usize` is 32-bit on wasm, so the scenarios and `state_hash` hash only fixed-width integers. `Fnv64` deliberately has no `write_usize`. Cast slots and counts to `u32` or `u64` explicitly before hashing.
- Add a test that the `Snapshot` buffer pointers (`as_ptr()`) and capacities are unchanged after 1,000 filled ticks. The zero-copy path depends on this.

## `trapiks-sim-wasm`

`Engine` now owns a `Sim` plus a preallocated snapshot:

```rust
#[wasm_bindgen]
impl Engine {
    pub fn load(bytes: &[u8], config: JsValue) -> Result<Engine, JsError>;
    pub fn meta(&self) -> Result<JsValue, JsError>;
    #[wasm_bindgen(js_name = roadGeometry)] pub fn road_geometry(&self) -> RoadGeometry;
    #[wasm_bindgen(js_name = nodeGeometry)] pub fn node_geometry(&self) -> NodeGeometry;
    #[wasm_bindgen(js_name = areaGeometry)] pub fn area_geometry(&self) -> AreaGeometry;
    pub fn step(&mut self);
    pub fn tick(&self) -> f64;
    #[wasm_bindgen(js_name = fillSnapshot)] pub fn fill_snapshot(&mut self) -> u32;
    #[wasm_bindgen(js_name = snapshotPointers)] pub fn snapshot_pointers(&self) -> SnapshotPointers;
    pub fn stats(&self) -> Result<JsValue, JsError>;
    #[wasm_bindgen(js_name = roadSpeedRatio)] pub fn road_speed_ratio(&self) -> Vec<f32>;
}
```

- **`load(bytes, config)`:** `config` is a `SimConfig` deserialized with `serde_wasm_bindgen`.
- **Large integers:** every `u64` that crosses the boundary (`seed`, `tick`) stays below 2^53. `build-wasm.sh` exports the types with `TS_RS_LARGE_INT=number` next to `TS_RS_EXPORT_DIR`, so ts-rs types them as `number`, which matches what `serde_wasm_bindgen` sends.
- **Snapshot buffers:** allocated in `load` with `Vec::with_capacity(MAX_VEHICLES)` for each column (`ids`, `x`, `y`, `heading`, `style`), so they never reallocate.
- **`fill_snapshot`:** fills the buffers via `Sim::fill_snapshot`, asserts `debug_assert!(count <= capacity)`, and returns the count.
- **`SnapshotPointers`:** a `#[wasm_bindgen]` struct with getters `ids`, `x`, `y`, `heading` and `style`, each returning `as_ptr() as u32`, plus `capacity`, the `u32` capacity of the `Vec`s. TS never hard-codes the capacity.
- **`roadSpeedRatio`:** fills a local `Vec` via `Sim::road_speed_ratio(&self, &mut out)` and returns it.
- **`tick()`:** returns `f64`, because JS numbers are exact up to 2^53.
- **`stateHash()`:** returns 16 lowercase hex digits.
- **Scenario exports:** under a `fixtures` cargo feature (`fixtures = ["trapiks-sim-core/fixtures"]`), `#[wasm_bindgen(js_name = runScenario)] pub fn run_scenario(name: &str) -> Result<String, JsError>`. It returns the computed hash and the expected constant as `"{computed} {expected}"` in hex. `build-wasm.sh` never enables this feature.

## Determinism check (`scripts/check-wasm-determinism.mjs`)

1. Builds `trapiks-sim-wasm` for `wasm32-unknown-unknown --release --features fixtures --target-dir target/wasm-fixtures`. A separate target dir keeps this build and `build-wasm.sh` incremental, because cargo fingerprints include features.
2. Runs `wasm-bindgen --target nodejs` on `target/wasm-fixtures/wasm32-unknown-unknown/release/trapiks_sim_wasm.wasm` into `target/wasm-fixtures/pkg`. That is outside `web/`, whose `"type": "module"` would break the CommonJS output.
3. Reuses the wasm-bindgen version check from `build-wasm.sh`, factored into `scripts/lib/wasm-bindgen-version.sh` and sourced by both.
4. Loads the result with `createRequire(import.meta.url)`. It instantiates synchronously. Then it calls `runScenario('four_way_5000')` and `runScenario('grid_city_demand_1000')`.
5. Exits with 1 unless computed equals expected for both, printing both values.

`scripts/check.sh` runs it after `cargo test`.

## Protocol (`web/src/sim/protocol.ts`)

**Main → worker:**

| Message | Contents |
|---|---|
| `load` | `{ type: 'load'; url: string; config: SimConfig }` |
| `speed` | `{ type: 'speed'; speed: Speed }`, where `type Speed = 0 \| 1 \| 2 \| 4 \| 8 \| 'max'` |
| `buffers` | `{ type: 'buffers'; buffers: SnapshotBuffers }` returns consumed buffers, with their `ArrayBuffer`s transferred |

**Worker → main:**

| Message | Contents |
|---|---|
| `ready` | As in M4 |
| `error` | As in M4 |
| `snapshot` | `{ type: 'snapshot'; tick: number; simTime: number; count: number; buffers: SnapshotBuffers }` |
| `stats` | `{ type: 'stats'; stats: StatsSnapshot; roadSpeedRatio: Float32Array }` |

- `SnapshotBuffers { ids: Uint32Array; x: Float32Array; y: Float32Array; heading: Float32Array; style: Uint8Array }`. Every array has length ≥ `count`.
- `SimConfig`, `SimMode` and `StatsSnapshot` come from `web/src/generated/`.
- Guards cover every message type.

## Worker (`web/src/worker/`)

| File | Content |
|---|---|
| `sim.worker.ts` | Message routing only. A second `load` is ignored. A `speed` message that arrives before `ready` is stored and applied |
| `engine-session.ts` | Holds the `Engine`, the wasm `memory` (from the `init()` return value), the views and the speed (default 1). Supplies `onTick` to the loop |
| `memory-views.ts` | `class MemoryViews`: builds the typed-array views over `memory.buffer` from `SnapshotPointers`, with length `capacity`. `refresh()` rebuilds them whenever `memory.buffer !== this.buffer`. Call it after every step batch and before every read |
| `buffer-pool.ts` | Keeps returned `SnapshotBuffers`, at most 3 sets. `take(count)` returns a set with capacity ≥ `count`, reusing when possible or allocating `ceil(count / 4096) × 4096` otherwise. `give(buffers)` drops a set smaller than the last `take` size |
| `loop.ts` | `startWallTicks(onTick, periodMs) → { stop }`: scheduling only, testable with `vi.useFakeTimers` |

**`startWallTicks`:**
- It keeps `next`. After each tick: `next += period`. If `now − next > period`, set `next = now`, which resyncs after a stall instead of bursting. Then `setTimeout(tick, max(0, next − now))`.

**`onTick`** (`engine-session.ts`):
1. Run steps. The time check comes after each step, so at least one step always runs when the speed is not 0.
   - For a numeric speed `k`, run `k` steps, but stop early once 90 ms of wall time have passed.
   - For `'max'`, run steps until 90 ms have passed.
2. `fillSnapshot`, then `views.refresh()`. Copy with one `pooled.<column>.set(views.<column>.subarray(0, count))` per column, then post the snapshot with the underlying `ArrayBuffer`s transferred.
3. Every 10th wall tick, post `stats`, with `roadSpeedRatio` transferred.
4. At speed 0, still post a snapshot every wall tick, with an unchanged tick, so the renderer settles.

## Main thread

| File | Content |
|---|---|
| `sim/client.ts` | `startSim(url, config, handlers)` returns a `SimClient` with `setSpeed(speed)` and `returnBuffers(buffers)`. Handlers: `onReady`, `onSnapshot`, `onStats`, `onError` |
| `sim/interpolation.ts` | Pure logic, detailed below |
| `render/palette.ts` | Adds `VEHICLE_COLORS`, the 9 colours from plan §4 |
| `render/vehicle-texture.ts` | Builds a white 44 × 19 px rounded-rect texture (4.4 × 1.9 m at 10 px/m) with a dark windshield bar at 70 % of its length. It draws a `Graphics`, then calls `renderer.generateTexture({ target, resolution: 4, antialias: true })` |
| `render/vehicle-layer.ts` | Detailed below |
| `hud/speed-control.ts` | Detailed below |
| `hud/debug-overlay.ts` | Adds `vehicles {n} · tick {t}` and sets `data-vehicles` and `data-tick` attributes |
| `app/debug-scene.ts` | Wires everything. The URL parameter `?vph=<number>` (default 3000, clamped to 0–200000) sets the demand. The seed is 1 and the mode is `City` |

**`sim/interpolation.ts`** (pure logic, no Pixi):
- `class SnapshotHistory` keeps the previous and current snapshots, each with its receive time.
- `push(snapshot, now)` returns the snapshot it evicted, so its buffers can go back to the worker.
- `sample(now, out: VehicleFrame)`:
    - The display deliberately lags one wall tick: at `alpha = 0` it shows `previous`.
  - With only one snapshot, it outputs `current` unchanged.
  - `interval = clamp(current.receivedAt − previous.receivedAt, 1, 250)`, and `alpha = clamp((now − current.receivedAt) / interval, 0, 1)`.
  - On each `push`, build `prevIndex: Int32Array`, which maps each current vehicle to its index in `previous`, or −1 for a new id. Use a temporary `Map` for this. `sample` then only indexes arrays.
  - Lerp the position. For the heading, `d = ((b − a + π) mod 2π + 2π) mod 2π − π`, and the result is `a + alpha·d`. A new id uses the current values.
  - Output goes to a `VehicleFrame { count; x; y; heading; style }` whose arrays are resized on demand to `count` rounded up to 4096, and never shrunk.

**`render/vehicle-layer.ts`:**
- One `ParticleContainer`, added to `world` after the road graphics, with `dynamicProperties: { position: true, rotation: true, color: true }`. Colour must be dynamic: pool slots change vehicles every frame, and static attributes only re-upload on add or remove.
- It holds a pool of `Particle`s, each created with `anchorX: 0.5, anchorY: 0.5, scaleX: 0.1, scaleY: 0.1`, so 10 px/m matches world metres.
- Each frame:
  - Grow the pool as needed.
  - Set `x`, `y`, `rotation`, `tint` (from `VEHICLE_COLORS[style]`) and `alpha = 1` on the used slots.
  - Set `alpha = 0` on the unused ones.
- Update from the Pixi ticker.

**`hud/speed-control.ts`:**
- A row of `.chip` buttons: `⏸ 1× 2× 4× 8× Max`. The default speed is 1.
- **Keys:** one `keydown` listener on `window`.
  - Digits: `1→1, 2→2, 3→4, 4→8, 5→max`.
  - Space toggles pause and restores the previous non-zero speed.
  - The listener calls `preventDefault()` and ignores events whose target is a button.
- The active button gets class `active`.
- The current speed goes to `#debug` as `data-speed` (`0`, `1`, `2`, `4`, `8` or `max`).

  - `interpolation.test.ts`: lerp at alpha 0, 0.5 and 1; heading wraps across ±π by the shortest arc; a new id snaps; the evicted snapshot is returned.

  - `protocol.test.ts`: new message guards.

  - `expect.poll` on `#debug[data-vehicles]` > 0, with `timeout: 10_000`.

  - Press Space: `data-speed` becomes `0`. Then `waitForTimeout(700)`, read `t1`, `waitForTimeout(1000)`, read `t2`, and assert `t2 === t1`.
  - No console errors or page errors.
  - Screenshot with `testInfo.outputPath('vehicles.png')`.
