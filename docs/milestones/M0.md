# M0: tooling and scaffold

Goal: an empty but fully wired project. Every quality gate runs and passes. A browser page loads the wasm module inside a Web Worker and shows the title "Trapiks" plus engine info that comes from Rust.

Do not modify `CLAUDE.md`, `docs/` or `.claude/`; the orchestrator owns them.

### Scripts

`scripts/build-wasm.sh`, a bash script using `set -euo pipefail` that `cd`s to the repo root. It:
1. Reads the `wasm-bindgen` version from `Cargo.lock`. It fails with a clear message if `wasm-bindgen --version` differs.
2. Runs `cargo build -p trapiks-sim-wasm --target wasm32-unknown-unknown --release`.
3. Runs `wasm-bindgen --target web --out-dir web/src/wasm/pkg target/wasm32-unknown-unknown/release/trapiks_sim_wasm.wasm`.
4. Runs `wasm-opt -O3` in place on `web/src/wasm/pkg/trapiks_sim_wasm_bg.wasm`, with `--enable-bulk-memory --enable-nontrapping-float-to-int --enable-sign-ext --enable-mutable-globals --enable-reference-types --enable-multivalue`. When `wasm-opt` is not on `PATH`, it prints a warning to stderr and skips this step.
5. Runs `TS_RS_EXPORT_DIR="$PWD/web/src/generated" cargo test -p trapiks-sim-core export_bindings` to export the ts-rs types.

`scripts/check.sh`, a bash script using `set -euo pipefail` that `cd`s to the repo root. It runs these in order, stopping at the first failure:
1. `cargo fmt --all --check`
2. `cargo clippy --workspace --all-targets -- -D warnings`
3. `cargo test --workspace`
4. `pnpm --dir web install --frozen-lockfile`
5. `pnpm --dir web build`
6. `pnpm --dir web typecheck`, `lint`, `format`, `test` and `check:comments`

It prints `ALL CHECKS PASSED` at the end.

`scripts/check-no-comments.mjs`, a Node ESM script with zero comments. It exits with code 1 and prints `file:line` for every comment found. It checks two sets of files:
- **TypeScript:** every `.ts` file under `web/src`, excluding `web/src/generated` and `web/src/wasm`, plus the root-level `web/*.ts` config files.
  - Tokenize with the TypeScript scanner.
  - Resolve `typescript` from `web/package.json` via `createRequire`.
  - Report every comment trivia, including `///` triple-slash directives. Never use triple-slash references anywhere.
- **Rust:** every `.rs` file under `crates/`.
  - Use a small scanner that skips string, raw string, byte string and char literals, including lifetimes such as `'a`, which are not char literals.
  - Report `//`, `///`, `//!` and `/* */`, except lines whose comment text starts with `// SAFETY:`.
  - Keep the functions small: split the scanning into per-literal-kind helpers.

   5. Stop the preview server afterwards.
3. **Gate probes.** Make each temporary change below, confirm that at least the named diagnostic appears, record the output line, then revert:
   1. A `//` comment in `web/src/hud/dom.ts` and one in `crates/sim-core/src/engine_info.rs`: `check:comments` reports both as `file:line`.

   4. A flat TS function with 9 sequential `if` statements: ESLint reports `sonarjs/cognitive-complexity`.
   5. A TS function with 5 nested `if` levels: ESLint reports `max-depth`.
