# M6: junction rules

Goal: vehicles obey junction control:
- They stop at red and handle amber.
- They yield by rank, using kinematic arrival times.
- They stop at stop signs and take turns at all-way stops.
- They keep out of full target lanes and full signal clusters.
- A long yield eventually times out, dropping only the courtesy margin.

After M6, vehicles in conflicting movements never overlap, and no junction can deadlock by mutual waiting.

This implements `docs/plan.md` §3.5 ("Entry rule", "Signals", "Priority rank"). Every value below is fixed.

## Constants

```rust
pub const DECISION_MARGIN: f64 = 5.0;
pub const CONFLICT_CLEAR_MARGIN: f64 = 5.0;
pub const PRIORITY_GAP: f64 = 2.5;
pub const MINOR_GAP: f64 = 4.0;
pub const STOPPED_SPEED: f64 = 0.5;
pub const STOP_LINE_WINDOW: f64 = 3.0;
pub const WAIT_TIMEOUT_TICKS: u64 = 300;
pub const APPROACH_SCAN: usize = 3;
```

## Conventions

- `s` is a vehicle's **front** position. Its body covers `[s − CAR_LENGTH, s]`.
- Every link → movement transition needs a commit, including at degree-2 nodes. This is what gives spillback along corridors.

## Vehicle state additions (`VehicleStore`)

| Field | Meaning |
|---|---|
| `committed: Vec<bool>` | Set when the entry rule passes. Cleared when the vehicle enters the movement |
| `arrival_tick: Vec<u64>` | Set when the vehicle first enters the decision zone of its current link. `u64::MAX` otherwise |
| `wait_start: Vec<u64>` | Set to the current tick on zone entry, and again every tick in which `signal_allows` or `stop_satisfied` fails |
| `stopped_at_line: Vec<bool>` | Set once `v < STOPPED_SPEED` while `span_end − s ≤ STOP_LINE_WINDOW + IDM_MIN_GAP` |

- All fields reset when the vehicle leaves the link.
- All four are included in `state_hash`.

## Occupancy additions (M5 `occupancy.rs`)

- `range(key) -> &[Entry]`: the sorted entries for a key, front first. Pending entries are excluded.
- `count(key) -> usize`: `range` plus the pending entries.
- `index_of(slot) -> usize`: already exists in M5, as the per-slot index.

## Definitions

- **Decision zone:** a link-placed vehicle is in its zone when the route has a next link and `span_end − s ≤ v²/(2·IDM_COMFORT_DECEL) + DECISION_MARGIN`.
- **The vehicle's movement:** `m`, which is `(to_node, movement_index(link, route[cursor+1]))`.
- **Node control:** from `nodes.control`.
  - Signal state is `network.signal_state(link, tick)`, where `None` means unsignalized.
  - A **minor approach** at a `Stop` or `Yield` node is one whose incoming class rank is below the node's highest incoming class rank.
- **Signal priority** of the vehicle's current link `L`:
  - 1 if `signal_state(L)` is `Green` or `Amber`, or if `L` is internal to a cluster.
  - Otherwise 0.
- **Effective rank** of a vehicle: `(signal_priority, m.rank.0, m.rank.1)`, compared lexicographically.
  - At an `AllWayStop` node, every vehicle has rank `(0, 0, 0)`.
- **Beats:** A beats B when A's effective rank is higher. On a tie, the earlier `arrival_tick` wins, then the lower id. This is a strict total order.
  - Vehicles on internal cluster links tie with green approaches and nearly always have the earlier arrival tick. They therefore clear the box first, which is intended.
- **Kinematic time:** `time_to(d, v, v0) = max((−v + libm::sqrt(v² + 2·IDM_MAX_ACCEL·d)) / IDM_MAX_ACCEL, d / v0)`.

## Entry rule (`src/vehicle/entry.rs`)

`pub fn may_enter(ctx: &RuleContext, slot: u32) -> bool` passes only when every check passes. The checks are evaluated cheapest first, each as its own small `pub` function.

1. **`signal_allows`:**
   - No signal, or `Green`: pass.
   - `Red`: fail.
   - `Amber`: pass only if `span_end − s ≤ v²/(2·IDM_COMFORT_DECEL)`, meaning the vehicle cannot stop.
   - Vehicles usually commit on entering the zone during green, so the amber branch matters mainly for vehicles held back by another rule.
2. **`stop_satisfied`:** at an `AllWayStop` node, or on a minor approach of a `Stop` node, the vehicle must have `stopped_at_line`. Otherwise pass.
3. **`has_space`:**
   - Let `target = route[cursor+1]` and `lane` be the landing lane.
   - `n` = the vehicles in movement `m` (`count`) plus the committed vehicles ahead of this one on its `(link, lane)` whose next movement is `m`. Walk forward from this vehicle's occupancy index, and stop as soon as `required` exceeds the free space.
   - `required = (CAR_LENGTH + IDM_MIN_GAP) × (1 + n)`.
   - `free` = `last.s − span_start` for the last vehicle on `(target, lane)`, or `span_end − span_start` when the lane is empty.
   - Pass when `free ≥ required`, or when the lane is empty and `n = 0`.
   - **Signal clusters:** when the node belongs to a cluster and the current link is an approach, additionally walk the route past every internal link. The first non-internal link must have at least one lane with `free ≥ CAR_LENGTH + IDM_MIN_GAP`. A route ending inside the cluster passes.
4. **`conflicts_clear`:** for each conflict `c` of `m` (with movement `m2`), no vehicle in `m2` may have `s < c.s_other + CONFLICT_CLEAR_MARGIN`. This checks movement occupancy only.
5. **`no_priority_approach`:** for each conflict `c` of `m` (with movement `m2`):
   - **Candidates:** for each lane in `m2.from_lanes`, walk `range((m2.from_link, lane))` from the front, over at most `APPROACH_SCAN` entries. Take the first vehicle whose next movement is `m2`.
   - **Skip** a candidate B when B is not committed and its own `signal_allows`, `stop_satisfied` or `has_space` fails.
   - **Times:**
     - `t_B = time_to(dist_to_stop_line(B) + c.s_other, v_B, v0_B)`.
     - `t_self = time_to(span_end − s + c.s_self + CONFLICT_CLEAR_MARGIN, v, v0)`.
   - **Gap:**
     - `MINOR_GAP` on a minor approach, otherwise `PRIORITY_GAP`.
     - `0` once `tick − wait_start ≥ WAIT_TIMEOUT_TICKS`. The timeout drops only the courtesy margin.
   - **Fail** when `(B.committed || beats(B, self)) && t_B ≤ t_self + gap`.

`RuleContext` holds `&Network`, `&VehicleStore`, `&Occupancy` and `tick`. `Sim::rule_context(&self) -> RuleContext` is `pub`, so tests can call the checks directly.

## Step changes (`Sim::step`)

After rebuilding the occupancy and before computing accelerations:

- **2a. Zone bookkeeping**, for every live link-placed vehicle in slot order: update `arrival_tick`, `wait_start` and `stopped_at_line`.
- **2b. Decisions:**
  1. Collect the candidates: vehicles in their zone that are not committed.
  2. Sort by `(effective rank descending, arrival_tick, id)` with `sort_unstable_by_key` on integer keys.
  3. Evaluate `may_enter` sequentially in that order.
  4. On a pass, set `committed = true` immediately. Later candidates in the same pass see earlier commits through `has_space` and rule 5.

In the acceleration pass:
- A link-placed vehicle that is in its zone and not committed gets a stop-line obstacle: `gap = span_end − s`, with leader speed 0.
- It uses whichever of the stop line and the vehicle leader has the smaller gap.

Transitions:
- A link → movement transition only happens when the vehicle is committed.
- An uncommitted vehicle whose `s` would pass `span_end` is clamped to `span_end` with `v = 0`.
- Entering a movement resets the four new fields.

Known behaviour, not a bug: a vehicle committed on the last green tick can still be in the box up to about 1 s into the next green. Cross traffic waits for it through rule 5.

## Tests (`crates/sim-core/tests/`)

### Support helpers (`tests/support/`)

- `run_until(sim, max_ticks, predicate) -> bool`.
- `check_invariants(sim)`, which asserts:
  - No NaN, and `v ≥ 0`.
  - On every link lane and within every movement, `leader.s − follower.s ≥ CAR_LENGTH`.
  - For every crossing (non-merge) conflict, the point is never inside both bodies at once. For each vehicle, the point lies inside the body when `c ∈ [s − CAR_LENGTH − 1.6, s + 1.6]`.
- `random_routes(map, rng, len)`: builds valid 2- or 3-link routes from junction movements. Use seed `Pcg32::new(2024, 7)` wherever randomness is needed.

### Test list

1. **`signal_red_stop`:** on `four_way(2, 200.0)`, spawn an east-approach vehicle (link 2) at tick 0, while phase 0 (north–south) is green. It stops with `s ≤ span_end`, is still stopped at tick 349, and commits at or after tick 350.
2. **`signal_amber`:** on `four_way(2, 200.0)` (v0 = 16.7 m/s, span ≈ 192.6 m), spawn north-approach vehicles V1 at tick 190 and V2 at tick 220.
   - V1 is in a movement by tick 330.
   - V2 is on link 0 with `v < STOPPED_SPEED` at tick 350, and commits at or after tick 1050.
3. **`permissive_left`:** a north-approach left-turner, with south-approach through vehicles spawned every 30 ticks for 400 ticks.
   - `check_invariants` holds every tick.
   - The left-turner commits before tick 1400.
4. **`t_junction_priority`:** on `t_junction()`, a platoon of 5 west-approach through vehicles 30 ticks apart, then a 200-tick gap. A minor vehicle is timed to reach its line mid-platoon.
   - The minor commits only after the last platoon vehicle has passed the conflict.
   - Every major vehicle keeps `v ≥ 0.8 · v0` while within 20 m of the node.
5. **`stop_sign`:** `t_junction` with `Control::Stop` at node 0. The minor vehicle has `stopped_at_line` set before it commits.
6. **`all_way_stop`:** `four_way` with `Control::AllWayStop`, one vehicle on each of the 4 approaches, spawned 5 ticks apart with through routes. They commit in arrival order and all despawn within 2,000 ticks.
7. **`spillback`:** on `four_way(1, 200.0)`:
   - Spawn A on the east exit link (link 3) with a single-link route, and spawn B on link 0, routed `[0, 3]`, 180 m back.
   - Without stepping, `has_space(&sim.rule_context(), b)` is false, because A is in `pending`.
   - `run_until` A's `s − span_start ≥ CAR_LENGTH + IDM_MIN_GAP`, then assert `has_space` is true.
8. **`cluster_flow`:** on `dual_carriageway_cross()`, spawn one vehicle every 20 ticks for 3,000 ticks, on an approach and route chosen by the seeded RNG from `random_routes`.
   - `check_invariants` holds every tick.
   - Internal links never get a signal state.
   - Every vehicle despawns within 3,000 ticks of spawning.
9. **`timeout`:** on `t_junction()`, spawn major west-approach through vehicles every 60 ticks (about 100 m apart, 6 s headway), plus one minor vehicle.
   - The minor commits no earlier than `wait_start + WAIT_TIMEOUT_TICKS`.
   - It does commit within 1,500 ticks.
   - `check_invariants` holds throughout.
10. **`low_demand_all_fixtures`:** on `four_way`, `t_junction`, `one_way_pair` and `dual_carriageway_cross`, spawn every 40 ticks using `random_routes`, for 6,000 ticks.
    - Invariants hold.
    - Every vehicle despawns within 3,000 ticks.
11. **`determinism_m5.rs`:** update `FOUR_WAY_HASH_5000`, since the rules change the trajectories. Two runs still match.

## Notes for later milestones

- A vehicle that stalls inside a movement still blocks crossing traffic. If the M7 real-map bench shows gridlock, the fallback is a conflict obstacle in the acceleration pass: a vehicle brakes for a crossing conflict ahead of it that is covered by, or will be taken by, a vehicle that beats it. Because `beats` is a total order, this cannot cycle.
- `link_span` recomputes setbacks on every call. If the M7 bench flags it, cache the spans per link.
