# M5: vehicles core

Goal: vehicles move deterministically along explicit routes with IDM car-following. They traverse links and junction movements, change lanes only at link entry, and despawn at the end of their route. There are no junction entry rules yet: every vehicle enters every movement. Rules come in M6, and demand and routing come in M7.

Follow `docs/plan.md` §3.5. Every value below is fixed.

Overlap in M5, which is expected:
- Crossing movements pass through each other.
- On merges, two vehicles can land on the same lane at a similar `s`. The gap clamp then gives a large deceleration, and the follower stalls at the movement end until the gap opens.
- This is NaN-free and never deadlocks, so it is acceptable for M5's tests. The no-overlap invariant belongs to M6.
- The right turn at `four_way` is a tight 4 m path. A curve speed cap is an M6/M9 concern.

## `src/rng.rs`: PCG32 (XSH RR 64/32)

- `pub struct Pcg32 { state: u64, inc: u64 }`, which derives `Clone`, `Debug` and `PartialEq`.
- `new(seed: u64, stream: u64)` follows the reference `pcg32_srandom_r`: set `state = 0` and `inc = (stream << 1) | 1`, step once, add `seed`, then step again.
- The step is `state = state.wrapping_mul(6364136223846793005).wrapping_add(inc)`.
- `next_u32()` takes `old = state`, steps, then returns the XSH RR output of `old`: `xorshifted = (((old >> 18) ^ old) >> 27) as u32`, `rot = (old >> 59) as u32`, result `xorshifted.rotate_right(rot)`.
- `next_f64()` returns a value in `[0, 1)`: `((next_u32() >> 5) as f64 · 67108864 + (next_u32() >> 6) as f64) / 9007199254740992`.
- `below(n: u32) -> u32` requires `n ≥ 1` and is unbiased. With `threshold = n.wrapping_neg() % n`, it loops: `let r = next_u32(); if r >= threshold { return r % n }`.
- `state_words() -> (u64, u64)`, used for hashing.
- Test: `new(42, 54)` must yield `0xa15c02b7, 0x7b47f409, 0xba1d3330, 0x83d2f293, 0xbfa4784b, 0xcbed606e`.

## `src/vehicle/`

### `idm.rs`

`pub fn acceleration(v: f64, v0: f64, gap: f64, dv: f64) -> f64`:
- `s* = s0 + max(0, v·T + v·dv / (2·√(a·b)))`, using `libm::sqrt`.
- `r = v / v0`.
- The result is `a · (1 − r²·r² − (s* / gap)²)`.
- `gap` is clamped to at least 0.1. `dv = v − v_leader`.
- With no leader, `gap = f64::INFINITY`, and the interaction term is 0.

### `place.rs`

```rust
#[derive(Clone, Copy, Debug, PartialEq)]
pub enum Place {
    Link { link: LinkId, lane: u8 },
    Movement { node: u32, movement: u16, from_lane: u8, to_lane: u8 },
}
```

### `store.rs`: `VehicleStore`

- A slot-based SoA, preallocated to `MAX_VEHICLES`:
  - `alive: Vec<bool>`, `id: Vec<u32>`, `place: Vec<Place>`, `s: Vec<f64>`, `v: Vec<f64>`
  - `color: Vec<u8>`
  - `route_start: Vec<u32>`, `route_len: Vec<u16>`, `route_cursor: Vec<u16>`
  - `spawn_tick: Vec<u64>`
  - `free: Vec<u32>`, a LIFO free list
  - `next_id: u32` and `live: u32`
- **Route arena:** `routes: Vec<LinkId>`. A vehicle's route is `routes[start .. start + len]`, and `route_cursor` indexes its current link.
  - `dead_len` counts dead entries: freeing a slot adds its `route_len`, and compaction resets it to 0.
  - At the end of a step, when `dead_len` exceeds half the arena, compact it: copy live routes in slot order into a reusable scratch `Vec`, swap it in, and rewrite the starts.
  - Routes longer than 65,535 links are rejected with `SpawnError::TooLong`.
- **Slot allocation:** pop from `free`, or else push a new slot. Freeing pushes onto `free`. Ids come from `next_id` and are never reused.

### `occupancy.rs`

- Once per step, rebuild a reusable `Vec<Entry>` holding `(key, s, slot)` for every live vehicle.
  - The key is `Place::Link(link, lane)` or `Place::Movement(node, movement)`, encoded as a `u64` sort key: link places as `(0 << 63) | link << 8 | lane`, movement places as `(1 << 63) | node << 16 | movement`.
- Sort by `(key, s descending via total_cmp, slot)` with `sort_unstable_by`.
- Store, per slot, its index in the sorted list. `index_of(slot) -> Option<usize>` returns `None` for a vehicle that is still pending (spawned since the last rebuild).
- A vehicle's same-place leader is the previous entry when the keys match. For a pending vehicle, it is the last entry of the sorted range for its key, which excludes pending entries.
- The movement key deliberately omits `from_lane`/`to_lane`. In M5, `entry_lane` always picks the lowest lane, so a movement has one from-lane. `last_on` for a next movement must see every vehicle in it.
- `pending: Vec<Entry>` is cleared on every rebuild. `spawn` pushes its new vehicle's entry there.
- `last_on(key) -> Option<(slot, s)>` returns the vehicle with the smallest `s` at that key. It searches both the sorted range (by binary search, skipping `!alive[slot]`) and the pending entries with the same key.

### `leader.rs`

`pub fn leader(network: &Network, vehicles: &VehicleStore, occupancy: &Occupancy, slot: u32) -> Option<(f64 /*gap*/, f64 /*leader v*/)>`:
1. **Same place:** the previous entry in the occupancy list. Gap = `leader.s − self.s − CAR_LENGTH`.
2. **Otherwise, set `acc` = the end of the current place − `self.s`.** A link ends at `link_span(link).1`, and a movement ends at its `length`.
3. **Walk forward** through at most `LEADER_LOOKAHEAD_PLACES` next places, with a virtual cursor that increments on each movement → link step.
   - From a link, the next place is the movement `(to_node, movement_index(link, route[c+1]))`. From a movement, it is `Link { link: route[c+1], lane: to_lane }`.
   - For a movement not yet entered, `to_lane` comes from the landing-lane rule.
   - For each next place, if `last_on` finds a vehicle, return `acc + offset − CAR_LENGTH`. The `offset` is `leader.s − span_start` on a link, or `leader.s` on a movement.
   - Otherwise `acc += place length`, which is `span_end − span_start` or `length`.
4. **Stop with no leader** at the route end, or when a junction or movement is missing.

### `pose.rs`

- **On a link:** `Network::link_pose(link, s, lane)`.
- **On a movement:**
  - Take the point and tangent on the movement's primary path at `s`, using `pose_at` over `path`/`cumulative`.
  - Add a lateral correction along `perp_right(tangent)`: `lerp(Δfrom, Δto, smoothstep(u))`, where `u = s / length`, `smoothstep(u) = u²(3 − 2u)`, `Δfrom = lane_offset(from road, from_lane) − lane_offset(from road, primary.0)`, and `Δto` is the same for the to road.
- Heading is `libm::atan2(tangent.y, tangent.x)`.

### `lanes.rs`

- **`entry_lane(junction, from_link, to_link) -> Option<u8>`:** the lowest lane of the `from_lanes` range of movement `(from_link, to_link)`. It returns `None` when the movement is missing, and the vehicle is then despawned in step 5.
- **Landing lane** when entering a movement from `a` into `b`:
  - If the route has a link `c` after `b`, it is `entry_lane(junction at b's to-node, b, c)`.
  - Otherwise it is `min(primary_lanes.1, lanes(b) − 1)`.

## `src/sim.rs`: `Sim`

```rust
pub struct Sim {
    network: Network,
    vehicles: VehicleStore,
    occupancy: Occupancy,
    accel: Vec<f64>,
    rng: Pcg32,
    tick: u64,
}
```

- **`Sim::with_capacity(map: &MapData, seed: u64, capacity: usize) -> Sim`:** the RNG is `Pcg32::new(seed, 0x5452_4150_494b_5301)`.
- **`Sim::new(map, seed)`** calls `with_capacity(map, seed, MAX_VEHICLES)`.
- **`spawn(&mut self, route: &[LinkId]) -> Result<u32, SpawnError>`:**
  - Validates, in this order:
    1. The route is non-empty (`EmptyRoute`).
    2. The route has at most 65,535 links (`TooLong`).
    3. Every link is active (`InactiveLink`). `is_link_active` bounds-checks the id and returns false for an out-of-range id, never panicking.
    4. Consecutive links connect through an existing movement. `ensure_junction` is called at every intermediate node. `Disconnected(i)` gives the index of the first link of the failing pair.
    5. Capacity allows the spawn (`Full`).
    6. The entry gap at `span_start` of `route[0]` on the entry lane is at least `IDM_MIN_GAP + CAR_LENGTH`, using `last_on`, which includes pending entries (`Blocked`).
  - It places the vehicle at `s = span_start`. The lane is `entry_lane` toward `route[1]`, or 0 for a single-link route.
  - `v = min(v0, leader v)`, or `v0` when there is no leader within 50 m.
  - The colour is `rng.below(COLOR_COUNT)`.
  - Returns the vehicle id.
  - `SpawnError` variants: `EmptyRoute`, `TooLong`, `InactiveLink(LinkId)`, `Disconnected(usize)`, `Full`, `Blocked`.
  - On success, it pushes the vehicle's occupancy entry to `pending`.
- **`step(&mut self)`**, in this fixed order:
  1. For every live vehicle, in slot order, ensure the junctions at `link_to(route[cursor])` and at `link_to(route[cursor+1])`, when those links exist.
  2. Rebuild the occupancy.
  3. Compute every acceleration into `accel` (read-only pass). `v0` is the speed limit of the current link, or of `route[cursor+1]`'s road while in a movement.
  4. Integrate each live slot, in ascending slot order:
     - `v' = v + a·dt`.
     - If `v' < 0`: `s += −v² / (2a)` and `v = 0`.
     - Otherwise: `s += v·dt + ½·a·dt²` and `v = v'`.
  5. Advance places while `s` exceeds the current place's end, carrying the overflow. A link ends at `link_span(link).1`, and a movement at its `length`:
     - **Link → movement:** needs a next route link. Enter `(to_node, movement)` with the landing lane, and set `s = overflow`.
     - **Movement → link:** `cursor += 1`, `Place::Link { link, lane: to_lane }`, and `s = span_start + overflow`.
     - A vehicle is despawned when it passes the span end of its last link, or when its next movement or `entry_lane` no longer exists.
  6. Free the despawned slots, in ascending slot order.
  7. Compact the route arena if needed, then `tick += 1`.
- **Accessors:** `tick()`, `vehicle_count()`, `network()` and `vehicles()`.
- **`state_hash(&self) -> u64`:** `Fnv64` over:
  - `tick`, the RNG state words, `network.version()` and `live`
  - then, for each live slot in ascending order: the slot, `id`, the place (tag plus fields as u32), `s.to_bits()`, `v.to_bits()`, `route_cursor`, and the route link ids
- **`fill_snapshot(&self, out: &mut Snapshot)`:**
  - `Snapshot { pub ids: Vec<u32>, pub x: Vec<f32>, pub y: Vec<f32>, pub heading: Vec<f32>, pub style: Vec<u8> }`.
  - It clears the buffers and pushes every live vehicle in ascending slot order. `style` is the colour index.

## Tests (`crates/sim-core/tests/`)

1. **`rng.rs`:** the reference vector; `below(10)` always < 10; `next_f64` in `[0, 1)` over 10,000 draws.
2. **`idm.rs`:**
   - Free road from `v = 0` accelerates at `a`.
   - At `v = v0` with no leader, the acceleration is about 0.
   - A standing leader 10 m ahead at `v = 15` gives a strong deceleration (below −2).
   - An equilibrium gap at `v = v0 / 2` gives a near-zero result (|a| < 0.1) when `gap = s*/√(1 − r⁴)`.
3. **`vehicles_corridor.rs`:**
   - Spawn 30 vehicles on route `[link 0, link 2, link 4]` (all forward), one every 25 ticks, retrying while `Blocked`.
   - Run until all despawn, at most 6,000 ticks.
   - Every tick, same-lane gaps are ≥ 0 on the same link, no `s`/`v` is NaN, and `v ≥ 0`.
   - All 30 despawn.
4. **`vehicles_turns.rs`** (on `four_way(2, 200.0)`):
   - **Left turn:** a vehicle entering from the north (forward link 0, heading south) and leaving east (link 3, the backward link of road 1). Heading south then east is a left turn.
     - Its snapshot heading changes smoothly: the consecutive-tick change, wrapped to `(−π, π]`, stays below 0.3 rad.
     - Consecutive positions are within `v·dt + 0.5` m. This bound holds because a 2-link route has zero lateral correction.
     - It despawns at the end.
   - **Right turn:** link 0 to link 7, the backward link of road 3 heading west. Assert only position continuity and despawn; the 4 m right-turn path turns faster than 0.3 rad per tick.
5. **`spawn_errors.rs`:** each `SpawnError` variant is produced.
   - `Blocked`: spawn twice at once, which works through `pending`.
   - `Full`: use `Sim::with_capacity(…, 1)`, then spawn on a second link.
   - `InactiveLink`: on `one_way_pair()`, use link 7, the backward link of a 2/0 road, and also an out-of-range id.
   - `TooLong`: a 65,536-link route.
6. **`determinism_m5.rs`:**
   - On `four_way(2, 200.0)`, use `Sim::new(map, 7)` and a separate test RNG `Pcg32::new(99, 1)`. Every 10 ticks, spawn on movement number `test_rng.below(12)` of node 0's junction, with route `[from_link, to_link]`. Skip `Blocked` spawns.
   - Run 5,000 ticks twice, and the hashes must be equal.
   - Record the value as `const FOUR_WAY_HASH_5000: u64`. M8 will compare it against wasm.
7. **`snapshot.rs`:** the snapshot length equals `vehicle_count`, snapshot order equals live-slot order, and headings are finite.
