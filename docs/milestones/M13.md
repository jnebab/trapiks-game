# M13: game screens, saves, traffic layer, attribution

Goal: Trapiks becomes a complete game loop:
1. A title screen.
2. A challenge list.
3. A challenge screen: baseline, edits, evaluate, a result with stars.
4. A sandbox with a demand slider and a traffic layer.
5. Local saves, with Continue.

Plus the OSM attribution. After M13, the synthetic map is fully playable. The real map drops in when it is generated.

The UI is plain DOM and TypeScript with the `.chip` look, following `hud/styles.css`. No framework.

## Rust and wasm

- **`ChallengeRunner`**, a `#[wasm_bindgen]` class wrapping M12's `ChallengeRun`:
  - `new(bytes, challenge: JsValue, commands: JsValue)`
  - `advance(maxSteps) -> JsValue`, returning a `RunState`
  - `free()`
- **`Engine`:**
  - `load(bytes, config)` stays as in M8. The config is `SimConfig`, including `budget` and `mode`.
  - `commandLog() -> JsValue`, returning `EditCommand[]`.
  - `replay(commands) -> Result<(), JsError>` enqueues the commands and then calls `apply_queued`. Saves load through this.
    - When any command fails, it returns an error. The worker then discards that engine, rebuilds with an empty log, and posts a toast "Save could not be restored".
- **`score(challengeJson, baseline, after, cost) -> JsValue`**, returning a `Score`.
- The ts-rs exports now include `Challenge`, `Center`, `RunResult`, `RunState`, `Score`, `FailReason` and `SimMode`.

## Worker

**State:** the worker keeps the decompressed map bytes, so it can build new engines and runners without fetching again.

**Messages from the main thread:**

| Message | Effect |
|---|---|
| `{ type: 'startSandbox'; vehiclesPerHour: number; log?: EditCommand[] }` | Replaces the engine with a `City` config (`budget: null`) and replays `log` if given. Posts a fresh `ready` built from the post-replay engine (geometry, pills, meta), with `mode` `'sandbox'`, then `commandResults { results: [], delta: null, budget, log }` |
| `{ type: 'startChallenge'; challenge: Challenge; log?: EditCommand[] }` | Sets up a baseline and a live region engine (details below) |
| `{ type: 'evaluate' }` | Runs an evaluation (details below) |
| `{ type: 'setDemand'; vehiclesPerHour: number }` | Sandbox only. Enqueues `SetDemand` |

**Every engine replacement,** for sandbox and challenge alike, posts a fresh `ready` from the post-replay engine, followed by `commandResults { results: [], delta: null, budget, log }`. The main thread rebuilds its stores, tile indexes, picking and pills from each `ready`.

**`commandResults` carries `log: EditCommand[]`,** the engine's current command log. Saves are written from it, so there is no `getLog` round trip.

**`startChallenge`:**
1. Posts `runProgress { done: 0 }`, then creates the baseline `ChallengeRunner` with no commands.
2. Advances it inside the wall-tick loop by calling `advance(32)` repeatedly until 90 ms have elapsed or it reports `Finished`. Each wall tick posts `{ type: 'runProgress'; phase: 'baseline'; done; total }`.
   - On finishing, it posts `{ type: 'baseline'; result }`, keeps only the `RunResult`, and frees the runner.
3. Meanwhile, it builds the live region engine (`Region` config, the challenge seed, `vehicles_per_hour` and `budget`), replays `log`, and posts `ready`.
4. The live engine does not step until the baseline finishes, then it runs at the current speed.

**`evaluate`:**
1. The worker ignores `evaluate` until the baseline has arrived.
2. Takes the live engine's `commandLog()`, builds a `ChallengeRunner` with it, and advances it the same way, with `phase: 'evaluate'` in the progress messages. The live sim pauses meanwhile.
3. When it finishes, it posts `{ type: 'evaluation'; result; score }` and frees the runner. The score uses `score(challenge, baseline, after, budget.spent)`.
4. The main thread disables every edit (the inspector, Delete, Ctrl+Z and the Undo chip) while an evaluation runs.

Guards and `protocol.test.ts` cases cover every new message.

## Main thread

### Screens and routing (`web/src/app/`)

| File | Content |
|---|---|
| `router.ts` | Pure parsing of `location.hash`: `#/` is the title, then `#/challenges`, `#/challenge/<id>`, `#/sandbox`. Unknown routes go to the title. `navigate(route)` sets the hash, and a `hashchange` listener renders the screen. The debug query parameters (`map`, `vph`, `cx`, `cy`, `z`) keep working on every screen |
| `game.ts` | Owns the long-lived pieces (app, map view, worker client, stores) and swaps the screen overlays. The map view persists across screens |
| `screens/title.ts` | A full-screen overlay (details below) |
| `screens/challenges.ts` | A card grid (details below) |
| `screens/challenge.ts` | The challenge screen (details below) |
| `screens/result.ts` | The result modal (details below) |
| `screens/sandbox.ts` | The sandbox screen (details below) |

**`screens/title.ts`:**
- The wordmark "Trapiks" (Lexend 700, 72 px) and the tagline "Fix Metro Manila's traffic".
- Buttons: **Challenges**, **Sandbox**, and **Continue** when any save exists.
- The map shows behind the overlay at city zoom, slowly panning at 20 px/s, with the sandbox running at 3,000 vph.
- A credits line holds the attribution text.

**`screens/challenges.ts`:**
- A card grid loaded from `challenges/<map>.json`.
- Each card shows the name, blurb, budget, target (such as "−20 % delay") and best stars from saves (★ filled or ☆ empty).
- Clicking a card navigates to it.

**`screens/challenge.ts`:**
- **Top bar:** a back chip, the challenge name, `#budget` ("$ spent / budget"), the Undo chip and the speed control.
- **Bottom-left objective chip:** "Cut delay by 20 % · baseline 42.3 s", which shows "Measuring baseline… 37 %" until the baseline arrives.
- **Evaluate** button, enabled after the baseline. During an evaluation, a progress overlay reads "Evaluating… 64 %".
- The inspector from M11b.
- The camera flies to the region centre at a scale that fits the radius.
- The region boundary is drawn as a dashed `#8E8E8E` circle, 2 px, in `layers.overlay`.

**`screens/result.ts`:**
- A modal card with:
  - pass or fail
  - 3 stars
  - the improvement %, the throughput ratio % and the cost
  - the fail reasons, as short messages
- Buttons: **Keep fixing** closes it. **Next challenge** navigates to the next id, or to the list.

**`screens/sandbox.ts`:**
- **Top bar:** back, `#budget` ("Spent $X"), Undo, speed.
- A demand slider from 0 to 100,000 vph, in steps of 1,000, which sends `setDemand` on change, debounced by 300 ms.
- Stats chips: active vehicles, mean speed in km/h, and arrivals per hour.
- A traffic-layer toggle chip, also bound to the `T` key.

### Saves (`web/src/app/saves.ts`)

- **Key:** `trapiks:v1:<map_hash>:<mode>` where mode is `sandbox` or `challenge:<id>`.
- **Value:** `{ mapHash, mode, seed, log: EditCommand[], bestStars?: number, updatedAt: number }`.
- **Writing:** after each `commandResults`, it writes the message's `log` under the key for the mode that the message belongs to, debounced by 1 s. The pending write is flushed synchronously before any `start*` message is sent.
- **Sandbox saves:** also store `vehiclesPerHour`.
- **Stars:** evaluations update `bestStars` when they are higher.
- **Continue** opens the most recent save by `updatedAt`, among saves whose `mapHash` matches the loaded map.
- Opening a challenge card, or the sandbox, always loads that mode's save when one exists.
- A **Reset** chip on the challenge and sandbox screens clears that save and restarts with an empty log.
- **Loading:** a save whose `mapHash` differs from the loaded map's is ignored, with a toast "Save is for a different map".
- Every `localStorage` access is wrapped in try/catch, and the game works without storage.

### Traffic layer (`render/traffic-layer.ts`)

- **Classes by `roadSpeedRatio`:** `≥ 0.8` is free, with no overlay. `0.5–0.8` is slow, amber `#F2B33D`. `< 0.5` is jammed, red `#E5484D`.
- **Container:** `layers.traffic`, after the last markings container and before `selection`. It shows only on the city band, or on the detail band when the toggle is on.
- **Per visible tile**, one `Graphics` holding only the slow and jammed roads, stroked at the road's rendered width × 0.6 and alpha 0.85. The city band uses its exaggerated widths.
- It rebuilds every visible tile when a `stats` message arrives (1 Hz), at most 4 tiles per frame.

### Attribution

- **Real map:** a fixed bottom-right `.chip.attribution` in 11 px text: "© OpenStreetMap contributors (ODbL)", linking to `https://www.openstreetmap.org/copyright`.
- **Synthetic map:** "Synthetic map".
- It also shows on the title screen.
