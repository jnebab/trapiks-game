# M4: roads slice (wasm, worker, debug render)

Goal: prove the full pipeline with real data shapes before vehicles exist. The worker fetches and gunzips a map, loads it into wasm, and sends road, node and area arrays to the main thread. The main thread draws them with PixiJS, with pan and zoom. A committed Playwright smoke test checks all of this.

Map selection: `?map=<name>` loads `maps/<name>.bin.gz`. The default is `synthetic` until the real map exists.
- `name` must match `/^[a-z0-9-]+$/`; otherwise it falls back to `synthetic`.
- The main thread resolves the URL to an absolute one with `new URL(\`maps/${name}.bin.gz\`, document.baseURI).href` before sending it to the worker, because a relative URL inside a worker resolves against the worker script.

## Rust

### `trapiks-sim-core`

- **`src/render.rs`**, a pure function of `MapData`:
  - `pub struct RoadRender { pub point_start: Vec<u32>, pub x: Vec<f32>, pub y: Vec<f32>, pub class: Vec<u8>, pub lanes_forward: Vec<u8>, pub lanes_backward: Vec<u8>, pub layer: Vec<i8>, pub name: Vec<u32> }`
  - `pub struct NodeRender { pub x: Vec<f32>, pub y: Vec<f32>, pub control: Vec<u8> }`
  - `pub struct AreaRender { pub kind: Vec<u8>, pub ring_start: Vec<u32>, pub x: Vec<f32>, pub y: Vec<f32> }`
  - `pub fn road_render(map) -> RoadRender`, `node_render(map)` and `area_render(map)`. Each copies the SoA columns.
- **Numeric codes:**
  - `RoadClass::code(self) -> u8` and `RoadClass::ALL: [RoadClass; 15]`, where the code is the index in `ALL`, in declaration order.
  - The same for `Control` (`code`, `ALL`) and `AreaKind` (`code`, `ALL`).
  - Implement `code` as a `match`, and add a test that `ALL[code(c)] == c` for every variant.
- **`MapMeta`**, which derives `Serialize` and `TS` with `#[ts(export)]`:

  ```rust
  pub struct MapMeta {
      pub map_hash: String,
      pub road_count: u32,
      pub node_count: u32,
      pub area_ring_count: u32,
      pub class_names: Vec<RoadClass>,
      pub control_names: Vec<Control>,
      pub area_kind_names: Vec<AreaKind>,
      pub names: Vec<String>,
      pub bounds: [f32; 4],
  }
  ```

  - `map_hash` is 16 lowercase hex digits.
  - `bounds` is `[0, 0, 0, 0]` for a map with no road points.
  - `bounds` is the min/max of every road point, as `[min_x, min_y, max_x, max_y]`.
  - `RoadClass`, `Control` and `AreaKind` derive `TS` with `#[ts(export)]`, which exports them as string unions.
  - `pub fn map_meta(map, bytes) -> MapMeta` builds it.

### `trapiks-sim-wasm`

```rust
#[wasm_bindgen]
pub struct Engine { map: MapData, meta: MapMeta }

#[wasm_bindgen]
impl Engine {
    pub fn load(bytes: &[u8]) -> Result<Engine, JsError>;
    pub fn meta(&self) -> Result<JsValue, JsError>;
    #[wasm_bindgen(js_name = roadGeometry)] pub fn road_geometry(&self) -> RoadGeometry;
    #[wasm_bindgen(js_name = nodeGeometry)] pub fn node_geometry(&self) -> NodeGeometry;
    #[wasm_bindgen(js_name = areaGeometry)] pub fn area_geometry(&self) -> AreaGeometry;
}
```

- `load` calls `from_bytes`, then `map_meta`.
- `meta()` serializes with `serde_wasm_bindgen`.
- `RoadGeometry`, `NodeGeometry` and `AreaGeometry` are `#[wasm_bindgen]` structs that wrap the `render.rs` structs.
  - They expose one `#[wasm_bindgen(getter, js_name = …)]` property per column, returning `Vec<u32>`, `Vec<f32>`, `Vec<u8>` or `Vec<i8>`. wasm-bindgen returns JS-owned typed-array copies, typed `readonly` in the d.ts.
  - Property names:
    - Roads: `pointStart`, `x`, `y`, `classCode`, `lanesForward`, `lanesBackward`, `layer`, `name`.
    - Nodes: `x`, `y`, `controlCode`.
    - Areas: `kindCode`, `ringStart`, `x`, `y`.
- Remove the `engineInfo` export and delete `EngineInfo`, its test and its generated type. `MapMeta` replaces it.
- `MAP_FORMAT_VERSION` moves to `src/map/codec.rs`.

## Web

### Worker protocol (`web/src/sim/protocol.ts`)

- **Main → worker:** `interface LoadMessage { type: 'load'; url: string }`.
- **Worker → main:**
  - `ReadyMessage { type: 'ready'; meta: MapMeta; roads: RoadArrays; nodes: NodeArrays; areas: AreaArrays }`
  - `ErrorMessage { type: 'error'; message: string }`
  - `type WorkerMessage = ReadyMessage | ErrorMessage`
- The array interfaces:
  - `RoadArrays { pointStart: Uint32Array; x: Float32Array; y: Float32Array; classCode: Uint8Array; lanesForward: Uint8Array; lanesBackward: Uint8Array; layer: Int8Array; name: Uint32Array }`
  - `NodeArrays { x: Float32Array; y: Float32Array; controlCode: Uint8Array }`
  - `AreaArrays { kindCode: Uint8Array; ringStart: Uint32Array; x: Float32Array; y: Float32Array }`
- Type guards: `isWorkerMessage` checks `type` plus the presence of the typed arrays. It does not deep-validate `MapMeta`; there is an `isMapMeta` guard for the scalar fields.
- Every typed-array buffer is transferred with `postMessage(message, transferList)`.

### Worker (`web/src/worker/`)

| File | Content |
|---|---|
| `sim.worker.ts` | No top-level `await`, because messages posted before it resolves are dropped. Starts `const wasmReady = init();` and registers `self.onmessage = (event) => { void handleMessage(event); }`. `handleMessage` awaits `wasmReady`, then handles `load`: `fetchMap(url)`, then `Engine.load(bytes)`, then collects the geometry and posts `ready`. Any exception posts `error` with the message |
| `fetch-map.ts` | `export async function fetchMap(url: string): Promise<Uint8Array>` fetches the URL and throws on a non-OK status. It reads `new Uint8Array(await response.arrayBuffer())`. Only when the bytes start with `0x1f 0x8b` does it gunzip with `new Response(new Blob([bytes]).stream().pipeThrough(new DecompressionStream('gzip'))).arrayBuffer()`. Otherwise it returns the bytes as they are. Vite serves `.gz` files with `Content-Encoding: gzip`, so the browser has already decoded them, while static hosts serve them raw |
| `geometry.ts` | Converts the wasm geometry objects to the protocol arrays, then calls `.free()` on each wasm object. The getter results are already JS-owned copies, so they go straight into the transfer list |

Camera convention (`render/camera.ts`):
- `interface Camera { x: number; y: number; scale: number }`. `x, y` are the screen position of the world origin in px. World y already points down, so there is no flip.
- `worldToScreen(c, wx, wy) = (wx·scale + x, wy·scale + y)`, and `screenToWorld` is its inverse.
- `pan(c, dx, dy)` adds screen px to `x, y`.
- `zoomAt(c, sx, sy, factor, min, max)`: `s' = clamp(scale·factor, min, max)`, then `x' = sx − (sx − x)·(s'/scale)`, and likewise for `y`.
- `fitBounds(bounds, viewW, viewH, margin)`: `scale = clamp(min((viewW − 2·margin)/w, (viewH − 2·margin)/h))`, `x = viewW/2 − cx·scale`, `y = viewH/2 − cy·scale`.
- Scale limits are `0.02` to `40` px/m.

Layout CSS: `body { overflow: hidden; margin: 0 }`, `canvas { display: block }`, and `#debug { position: fixed; top: 8px; left: 8px }`.

Styles:
- Palette constants live in `render/palette.ts`, typed `as const`.
- Road class codes are resolved to names with `meta.class_names[code]`, never with a hand-written table.
