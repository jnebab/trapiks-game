# M4: roads slice (wasm, worker, debug render)

Goal: prove the full pipeline with real data shapes before vehicles exist. The worker fetches and gunzips a map, loads it into wasm, and sends road, node and area arrays to the main thread. The main thread draws them with PixiJS, with pan and zoom. A committed Playwright smoke test checks all of this.

Map selection: `?map=<name>` loads `maps/<name>.bin.gz`. The default is `synthetic` until the real map exists.

## Rust

### `trapiks-sim-core`

- **`src/render.rs`**, a pure function of `MapData`:
  - `pub struct RoadRender { pub point_start: Vec<u32>, pub x: Vec<f32>, pub y: Vec<f32>, pub class: Vec<u8>, pub lanes_forward: Vec<u8>, pub lanes_backward: Vec<u8>, pub layer: Vec<i8>, pub name: Vec<u32> }`
  - `pub struct NodeRender { pub x: Vec<f32>, pub y: Vec<f32>, pub control: Vec<u8> }`
  - `pub struct AreaRender { pub kind: Vec<u8>, pub ring_start: Vec<u32>, pub x: Vec<f32>, pub y: Vec<f32> }`
  - `pub fn road_render(map) -> RoadRender`, `node_render(map)` and `area_render(map)`. Each copies the SoA columns.
- **Numeric codes:**
  - `RoadClass::code(self) -> u8` and `RoadClass::ALL: [RoadClass; 15]`, where the code is the index in `ALL`, in declaration order.
  - The same for `Control` (`code`, `ALL`) and `AreaKind` (`code`, `ALL`).
  - Implement `code` as a `match`, and add a test that `ALL[code(c)] == c` for every variant.
- **`MapMeta`**, which derives `Serialize` and `TS` with `#[ts(export)]`:

  ```rust
  pub struct MapMeta {
      pub map_hash: String,
      pub road_count: u32,
      pub node_count: u32,
      pub area_ring_count: u32,
      pub class_names: Vec<RoadClass>,
      pub control_names: Vec<Control>,
      pub area_kind_names: Vec<AreaKind>,
      pub names: Vec<String>,
      pub bounds: [f32; 4],
  }
  ```

  - `map_hash` is 16 lowercase hex digits.
  - `bounds` is the min/max of every road point, as `[min_x, min_y, max_x, max_y]`.
  - `RoadClass`, `Control` and `AreaKind` derive `TS` too, which exports them as string unions.
  - `pub fn map_meta(map, bytes) -> MapMeta` builds it.

### `trapiks-sim-wasm`

```rust
#[wasm_bindgen]
pub struct Engine { map: MapData, meta: MapMeta }

#[wasm_bindgen]
impl Engine {
    pub fn load(bytes: &[u8]) -> Result<Engine, JsError>;
    pub fn meta(&self) -> Result<JsValue, JsError>;
    #[wasm_bindgen(js_name = roadGeometry)] pub fn road_geometry(&self) -> RoadGeometry;
    #[wasm_bindgen(js_name = nodeGeometry)] pub fn node_geometry(&self) -> NodeGeometry;
    #[wasm_bindgen(js_name = areaGeometry)] pub fn area_geometry(&self) -> AreaGeometry;
}
```

- `load` calls `from_bytes`, then `map_meta`.
- `meta()` serializes with `serde_wasm_bindgen`.
- `RoadGeometry`, `NodeGeometry` and `AreaGeometry` are `#[wasm_bindgen]` structs that wrap the `render.rs` structs.
  - They expose one getter per column, returning `Vec<u32>`, `Vec<f32>`, `Vec<u8>` or `Vec<i8>`. wasm-bindgen turns these into typed-array copies.
  - Getter names are camelCase via `js_name`, for example `pointStart`, `lanesForward`.
- Remove the `engineInfo` export and delete `EngineInfo`, its test and its generated type. `MapMeta` replaces it.
- `MAP_FORMAT_VERSION` moves to `src/map/codec.rs`.

## Web

### Worker protocol (`web/src/sim/protocol.ts`)

- **Main → worker:** `interface LoadMessage { type: 'load'; url: string }`.
- **Worker → main:**
  - `ReadyMessage { type: 'ready'; meta: MapMeta; roads: RoadArrays; nodes: NodeArrays; areas: AreaArrays }`
  - `ErrorMessage { type: 'error'; message: string }`
  - `type WorkerMessage = ReadyMessage | ErrorMessage`
- `RoadArrays` has `pointStart: Uint32Array; x: Float32Array; y: Float32Array; classCode: Uint8Array; lanesForward: Uint8Array; lanesBackward: Uint8Array; layer: Int8Array; name: Uint32Array`. `NodeArrays` and `AreaArrays` are analogous.
- Type guards: `isWorkerMessage` checks `type` plus the presence of the typed arrays. It does not deep-validate `MapMeta`; there is an `isMapMeta` guard for the scalar fields.
- Every typed-array buffer is transferred with `postMessage(message, transferList)`.

### Worker (`web/src/worker/`)

| File | Content |
|---|---|
| `sim.worker.ts` | Awaits wasm init, then handles `load`: calls `fetchMap(url)`, then `Engine.load(bytes)`, then collects the geometry and posts `ready`. Any exception posts `error` with the message |
| `fetch-map.ts` | `export async function fetchMap(url: string): Promise<Uint8Array>` fetches the URL, throws on a non-OK status, pipes the body through `new DecompressionStream('gzip')`, and returns the bytes |
| `geometry.ts` | Converts the wasm geometry objects to the protocol arrays and builds the transfer list |

### Main thread

| File | Content |
|---|---|
| `hud/title.ts` | Delete it. The title screen returns in M13 |
| `main.ts` | Bootstrap only: reads `?map`, creates the app, starts the sim client, and on `ready` draws the map and fits the camera to `meta.bounds`. On `error`, it shows the message in a `.chip` |
| `sim/client.ts` | `startSim(url, handlers: { onReady, onError }): Worker` |
| `render/app.ts` | `createApp(root): Promise<Application>`: a PixiJS 8 `Application` with `resizeTo: window`, background `#EEEDE6`, `antialias: true`, and a `world` container |
| `render/camera.ts` | Pure math, no Pixi imports: `interface Camera { x: number; y: number; scale: number }`, `fitBounds(bounds, viewW, viewH, margin): Camera`, `zoomAt(camera, screenX, screenY, factor, min, max): Camera` (the point under the cursor stays fixed), `pan(camera, dx, dy): Camera`, `worldToScreen(camera, x, y)` and `screenToWorld(camera, x, y)`. Scale limits are `0.02` to `40` px/m |
| `render/camera-input.ts` | Wires wheel zoom (factor `1.0015^(−deltaY)`), pointer-drag pan and a resize refit onto a camera state object, and applies it to the `world` container |
| `render/debug-roads.ts` | Draws the roads in one `Graphics`. First, all outlines: `#9B9B97`, width `lanes × 3.2 + 0.7`. Then all fills: white, width `lanes × 3.2`. Both use round joins. Elevated roads (`layer > 0`) are drawn after the ground roads with a `#151515` outline |
| `render/debug-areas.ts` | Draws the area rings: water `#A8C0F4`, parks `#CDE6A6` |
| `hud/debug-overlay.ts` | A top-left `.chip` with `id="debug"`, showing `FPS {n} · roads {n} · map {name}`. It updates twice a second from the Pixi ticker and sets `data-roads` and `data-fps` attributes for tests |

Styles:
- Palette constants live in `render/palette.ts`, typed `as const`.
- Road class codes are resolved to names with `meta.class_names[code]`, never with a hand-written table.
