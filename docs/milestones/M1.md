# M1: map model and road derivation

Goal: `trapiks-mapgen` reads Overpass JSON and produces a validated `MapData` holding roads, nodes, junction controls, names and turn bans. The format lives in `sim-core` so the sim and the wasm layer can load it later. Areas, the real map and the fetch scripts are M2.

Follow `docs/plan.md` §3.3 and §3.5. Every value below is fixed; do not re-decide it.

## `trapiks-sim-core` additions

### `src/fnv.rs`

- `pub fn fnv1a64(bytes: &[u8]) -> u64`: FNV-1a 64-bit (offset `0xcbf29ce484222325`, prime `0x100000001b3`).
- `pub struct Fnv64(u64)`, with `Default` (the offset basis) and:
  - `new()`
  - `write(&mut self, bytes: &[u8])`
  - `write_u32`, `write_u64`, `write_f64`, which hash the little-endian bytes
  - `finish()`

  It is used later by `state_hash`.

### `src/map/road_class.rs`

`#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)] pub enum RoadClass`. The table below lists the variants in declaration order.

Do not derive `PartialOrd` or `Ord`. Every comparison uses `rank()`.

| Variant | `rank()` | default lanes per direction | default kph | implies one-way |
|---|---|---|---|---|
| Motorway | 14 | 2 | 100 | yes |
| MotorwayLink | 13 | 1 | 60 | no |
| Trunk | 12 | 2 | 60 | no |
| TrunkLink | 11 | 1 | 40 | no |
| Primary | 10 | 2 | 60 | no |
| PrimaryLink | 9 | 1 | 40 | no |
| Secondary | 8 | 1 | 50 | no |
| SecondaryLink | 7 | 1 | 40 | no |
| Tertiary | 6 | 1 | 40 | no |
| TertiaryLink | 5 | 1 | 30 | no |
| Unclassified | 4 | 1 | 30 | no |
| Road | 3 | 1 | 30 | no |
| Residential | 3 | 1 | 20 | no |
| LivingStreet | 2 | 1 | 10 | no |
| Service | 1 | 1 | 15 | no |

- Methods: `rank(self) -> u8`, `default_lanes(self) -> u8`, `default_speed_kph(self) -> u8`, `implies_oneway(self) -> bool`.
- `pub fn from_highway(value: &str) -> Option<RoadClass>` maps the OSM `highway` values, for example `"motorway_link"` to `MotorwayLink`.
- Implement each method as a `match` returning a constant. Don't use a lookup table indexed by casts.

### `src/map/control.rs`

`#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord, Serialize, Deserialize)] pub enum Control { Priority, Yield, Stop, AllWayStop, Signal }`.

- The derive order defines precedence: `Signal` > `AllWayStop` > `Stop` > `Yield` > `Priority`. When several controls apply to one node, keep the maximum.

### `src/map/data.rs`

Every struct derives `Clone, Debug, PartialEq, Serialize, Deserialize, Default`, except where noted.

```rust
pub struct GeoOrigin { pub lat: f64, pub lon: f64 }

pub struct NodeTable { pub x: Vec<f32>, pub y: Vec<f32>, pub control: Vec<Control> }

pub struct RoadTable {
    pub from: Vec<u32>,
    pub to: Vec<u32>,
    pub class: Vec<RoadClass>,
    pub lanes_forward: Vec<u8>,
    pub lanes_backward: Vec<u8>,
    pub speed_kph: Vec<u8>,
    pub layer: Vec<i8>,
    pub name: Vec<u32>,
    pub point_start: Vec<u32>,
}

pub struct PointTable { pub x: Vec<f32>, pub y: Vec<f32> }

pub struct TurnBan { pub via_node: u32, pub from_road: u32, pub to_road: u32 }

pub struct MapData {
    pub origin: GeoOrigin,
    pub nodes: NodeTable,
    pub roads: RoadTable,
    pub points: PointTable,
    pub names: Vec<String>,
    pub turn_bans: Vec<TurnBan>,
}
```

Conventions:

- **Road geometry:**
  - Road `i` owns the points `point_start[i] .. point_start[i + 1]`. `point_start` has `road_count + 1` entries.
  - The first point equals the `from` node position and the last point equals the `to` node position. Every road has at least 2 points.
- **Direction:**
  - "Forward" means `from → to`.
  - `lanes_forward == 0` or `lanes_backward == 0` means a one-way road. A road never has both at 0.
- **Names:** `names[0]` is `""`, meaning unnamed. `name[i]` indexes into `names`. The rest of the table follows the order in which each name is first used while roads are emitted in output order.
- **Turn bans** are sorted by derived `Ord`, which is `(via_node, from_road, to_road)`, and deduplicated.
- **Accessors on `MapData`:**
  - `road_count()` and `node_count()`
  - `road_points(&self, road: u32) -> (&[f32], &[f32])`
- **`TurnBan`** derives `Copy, Eq, PartialOrd, Ord` as well.

### `src/map/validate.rs`

`pub fn validate(map: &MapData) -> Result<(), MapError>` checks that:
- every table has consistent lengths
- `from` and `to` indices are within the node count
- `point_start` starts at 0, grows by at least 2 per road, and ends at the point count
- no road has `from == to`
- `name` indices are within bounds
- no road has both lane counts at 0
- turn-ban indices are within bounds

Split it into one small function per table.

### `src/map/codec.rs`

- `pub const MAP_MAGIC: [u8; 4] = *b"TRPK";`
- **Format:** the magic, then `MAP_FORMAT_VERSION` as a little-endian `u32`, then the postcard payload.
- `pub fn to_bytes(map: &MapData) -> Result<Vec<u8>, MapError>`. It does not validate, which lets tests encode invalid maps.
- `pub fn from_bytes(bytes: &[u8]) -> Result<MapData, MapError>` checks the magic, then the version, decodes, then validates.
- `pub fn map_hash(bytes: &[u8]) -> u64` is `fnv1a64` over the full uncompressed bytes.

### `src/map/error.rs`

`#[derive(Debug, PartialEq, Eq)] pub enum MapError { BadMagic, UnsupportedVersion(u32), Decode(String), Encode(String), Invalid(String) }`, with `Display` and `std::error::Error` implemented.

### Module wiring

- `src/map/mod.rs` re-exports the public items.
- `lib.rs` declares `pub mod map;` and `pub mod fnv;`.
- `MAP_FORMAT_VERSION` stays in `engine_info.rs`.

### Tag rules (`tags.rs`)

- **`oneway(tags, class) -> Oneway { No, Forward, Backward }`**
  - `oneway=yes|true|1` gives `Forward`.
  - `oneway=-1|reverse` gives `Backward`.
  - `oneway=no` gives `No`.
  - Otherwise, `junction=roundabout|circular` or `class.implies_oneway()` gives `Forward`, and anything else gives `No`.
- **`lanes(tags, class, oneway) -> (u8, u8)`** returns the forward and backward lane counts.
  - **One-way:** the total is `lanes`, or else `class.default_lanes()`. That total goes to the travel direction and 0 to the other.
  - **Two-way with both `lanes:forward` and `lanes:backward`:** use them.
  - **Two-way with `lanes` and exactly one directional tag:** the other direction is `lanes − tagged`, at least 1.
  - **Two-way with only `lanes`:** forward is `ceil(n/2)` and backward is `floor(n/2)`, each at least 1.
  - **Two-way with nothing tagged:** the default for each direction.
  - Clamp every direction with lanes to `1..=8`.
  - A value that fails to parse counts as missing.
- **`speed_kph(tags, class) -> u8`** reads `maxspeed`.
  - `"60"` and `"60 km/h"` mean 60 km/h.
  - `"40 mph"` means `round(40 × 1.609)`.
  - Anything else falls back to the class default. Clamp to `5..=130`.
- **`layer(tags) -> i8`**
  - `layer` parsed as an integer, clamped to `-3..=5`.
  - Otherwise, `bridge` present and not `no` gives 1.
  - Otherwise, `tunnel` present and not `no` gives -1.
  - Otherwise 0.
- **`name(tags) -> Option<&str>`:** `name`, else `ref`.

### Filter (`filter.rs`)

`road_class(tags)` returns `None` when:
- `highway` is missing or unmapped
- `area=yes`
- `access` is `private` or `no`
- the road is a service road with `service` in `parking_aisle|driveway|drive-through|emergency_access`

Otherwise it returns `RoadClass::from_highway`.

### Projection (`project.rs`)

- `Projection::centered(min_lat, min_lon, max_lat, max_lon)` uses the bbox centre.
- `project(lat, lon) -> (f64, f64)`:
  - `x = R · (lon − lon0) · cos(lat0)`
  - `y = −R · (lat − lat0)`
  - Angles are in radians, and `R = 6_371_008.8`.
- The bbox covers every node used by a kept road.
- `GeoOrigin` is the centre.

### Topology (`topology.rs`)

1. Remove consecutive duplicate node ids in each kept way. Drop ways left with fewer than 2 nodes, and ways whose nodes lack coordinates.
2. **Junction nodes** are:
   - the first and last node of every kept way
   - every node referenced by 2 or more kept ways
   - every node that appears twice within one way
3. **Closed ways** (first node == last node): also treat the node at index `len / 2` as a junction. This guarantees that no road starts and ends at the same node.
4. **Split** each way into segments at its junction nodes. A segment is `{ way_id, node_ids, class, lanes_forward, lanes_backward, speed_kph, layer, name }`. For a `Backward` one-way, reverse the node order and store the travel direction as forward, so every one-way road ends up with `lanes_backward == 0`.
5. **Merge** chains. A junction node that is shared by exactly 2 segment ends, and by no other segment, joins those segments when their attributes are equal once orientation is aligned. Equality covers only `class`, `lanes_forward`, `lanes_backward`, `speed_kph`, `layer` and `name`; way ids and node ids never block a merge.
   - Never merge two segments whose outer endpoints are the same node, because the result would have `from == to`.
   - Reversing a segment swaps its forward and backward lanes. Two one-way segments merge only when their travel directions align.
   - A segment's key is `(way_id, index of the segment's first node within the way)`. A merged road's key is the minimum key over its segments.
   - Merge until nothing changes, visiting roads in key order.
6. **Output:**
   - Nodes are the remaining junction nodes, ordered by OSM node id.
   - Roads are ordered by their key.
   - Each road keeps its OSM node id sequence and its source way ids for the next steps. Neither is written to `MapData`.

### Control assignment (`controls.rs`)

- Collect control nodes: nodes with `highway` equal to `traffic_signals` (Signal), `stop` (Stop, or `AllWayStop` when also tagged `stop=all`) or `give_way` (Yield).
- For each road, walk its node sequence while accumulating arc length.
  - A control node at a road endpoint applies to that end node.
  - An interior control node applies to the `from` end when its distance from `from` is at most 25 m. Independently, it applies to the `to` end when its distance from `to` is at most 25 m.
- The node's control is the maximum over every control applied to it.

### Turn restrictions (`restrictions.rs`)

- Read relations with `type=restriction`. The value comes from `restriction`, or else `restriction:motorcar`.
- Members: `from` (way), `via` (node) and `to` (way). Skip the relation when the via member is a way, when a member is missing, or when there is more than one of either `from` or `to`.
- **Resolving roads:**
  - The from road is the road built from the from way that has the via node as an endpoint. The to road is found the same way from the to way.
  - When no such road exists, or more than one exists (an unsplit way that passes through the via node yields two), skip the relation.
- **`no_*`:** ban `(from_road, via_node, to_road)`.
- **`only_*`:** ban every road incident to the via node except `to_road` and `from_road`.

## Tests

- Use a small fixture builder, `tests/support/mod.rs`, that builds `OsmData` in code:
  - `node(id, lat, lon)`

  - `way(id, &[node ids], &[(k, v)])`
  - `restriction(id, kind, from_way, via_node, to_way)`
  - Way geometry is derived from the node coordinates.
- Place fixture coordinates around lat 14.6, lon 121.0.
- A spacing of 0.0001° is about 11 m.

Required tests:

1. `parses_overpass_json`: a small inline JSON string, passed to `input::parse` and then merged the same way `load` merges, with one node, one way (with geometry) and one relation parses through `osm.rs` + `input.rs`.
   - The way comes before the node in the JSON, and the node, tagged `highway=traffic_signals`, is also in the way's geometry. It must keep its tags after `load`.
   - A way whose geometry length differs from its node count is dropped.
2. `splits_crossing_ways`: two residential ways crossing at a shared node give 4 roads and 5 nodes.
3. `merges_equal_chain`:
   - One street split into 3 ways with equal tags gives 1 road.
   - The same street with different `lanes` on the middle way gives 3 roads.
   - The same street with its middle way drawn in the opposite direction still gives 1 road. Use asymmetric lane tags (`lanes:forward=2`, `lanes:backward=1` on the outer ways, swapped on the reversed middle way) to prove the lanes were swapped correctly.

   - Covers `oneway=yes`, `oneway=-1` (node order reversed, `lanes_backward == 0`), `junction=roundabout`, and `highway=motorway` untagged. Untagged `motorway_link` stays two-way.
   - Two `oneway=yes` ways meeting head-on at a degree-2 node do not merge.
5. `lane_rules`: two-way `lanes=4` gives (2,2). `lanes=3` gives (2,1). `lanes:forward=3` + `lanes:backward=1` gives (3,1). `lanes=3` + `lanes:backward=2` gives (1,2). Untagged residential gives (1,1). One-way `lanes=3` gives (3,0).

7. `layer_rules`: `layer=2` gives 2. `bridge=yes` gives 1. `tunnel=yes` gives -1. `layer=9` gives 5.
8. `filters`: `service=driveway`, `access=private`, `area=yes` and `highway=footway` are all excluded. `highway=service` without a subtype is kept.
9. `control_assignment`:

   - At about 44 m it does not.
   - A stop node on the junction itself makes it `Stop`.
   - A signal and a stop on the same junction give `Signal`.
   - A stop node tagged `stop=all` on the junction gives `AllWayStop`.
10. `restriction_expansion`:
    - `no_left_turn` at a 4-way gives 1 ban.
    - `only_straight_on` at a 4-way gives 2 bans.

    - A restriction whose from way continues through the via node, so that two roads from that way touch the via node, gives 0 bans.
11. `closed_way_has_no_self_loop`: a closed residential loop touched by one other way at one node produces no road with `from == to`, and `validate` passes.
