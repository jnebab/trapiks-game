# M11a: edit plumbing, live network updates, picking and highlighting

Goal: edits flow end to end.
- The main thread sends `EditCommand`s to the worker and quotes their costs.
- Results come back with a network delta, and the map redraws exactly the affected tiles.
- The player hovers a road to highlight it (cyan, as in reference shot 1), presses Delete to remove it, and presses Ctrl+Z to undo.

The full inspector UI is M11b.

Follow CLAUDE.md's boundary rules: commands are queued and applied at the start of the next step.

## Rust

### `sim-core`: `src/render/delta.rs`

```rust
pub struct NetworkDelta {
    pub roads: RoadRows,
    pub nodes: NodeRows,
    pub setbacks: SetbackRows,
    pub junctions: JunctionRows,
    pub markers: MarkerRows,
    pub pills: SignalPills,
}
```

- **`pub fn network_delta(network: &Network, roads: &[u32], nodes: &[u32]) -> NetworkDelta`:**
  - **Affected nodes:** the given nodes, plus both endpoints of every given road, sorted and deduplicated.
  - **`RoadRows`:** for each given road, `id`, `class`, `lanes_forward`, `lanes_backward`, `layer`, `name`, `deleted`, `from` and `to`, plus its geometry as `point_len` with `x`/`y` concatenated.
  - **`NodeRows`:** for each affected node, `id`, `x`, `y` and `control`.
  - **`SetbackRows`:** for every road incident to an affected node, `id` plus the two setbacks.
  - **`JunctionRows`:** for each affected node, its junction shape. A node that is no longer a junction gets an empty ring (`ring_len = 0`), so the client removes it.
  - **`MarkerRows`:** the approach markers of every link arriving at an affected node, plus `nodes`, the affected node list, so the client replaces every marker at those nodes.
  - **`pills`:** the full `signal_pills` list, since control edits can change clusters anywhere. It is small.
- Test `delta_contents`: `SetLanes` on road 1 of `four_way`.
  - The delta has 1 road row with the new lanes.
  - The affected nodes are 0 and 2.
  - Node 0's junction shape is recomputed, with a wider fillet on the east arm.
  - There are markers for the 4 approaches at node 0.

### `sim-wasm`: `Engine` additions

- `enqueue(command: JsValue) -> Result<u32, JsError>` deserializes an `EditCommand` and returns its sequence number.
- `quote(command: JsValue) -> Result<JsValue, JsError>` returns `{ Ok: cost } | { Err: EditError }`.
- `takeResults() -> Result<JsValue, JsError>` returns `Vec<CommandResult>`.
- `budget() -> Result<JsValue, JsError>` returns `{ limit: number | null, spent: number }`, as the ts-rs exported `BudgetState`.
- `delta(roads: Vec<u32>, nodes: Vec<u32>) -> DeltaGeometry` is a wasm-bindgen struct with typed-array getters for every column above, in camelCase.

## Protocol and worker

**Main → worker:**
- `{ type: 'command'; command: EditCommand }`
- `{ type: 'quote'; id: number; command: EditCommand }`

**Worker → main:**
- `{ type: 'quoteResult'; id: number; result: QuoteResult }`, where `QuoteResult` is `{ Ok: number } | { Err: EditError }`. It is sent right after the quote message.
- `{ type: 'commandResults'; results: CommandResult[]; delta: DeltaArrays | null; budget: BudgetState }`. It is sent after the wall tick in which the results appeared. `delta` covers the union of the changed ids of the successful results, and is `null` when there were none.

Guards and `protocol.test.ts` cases cover all four messages.

## Main thread

### `render/road-store.ts`: a growable road table

- A class holding every road column as typed arrays with doubling capacity, and geometry as `(start, len)` ranges into growable `x`/`y` arrays.
- It is built from `ready`, and `applyRoads(rows)` updates existing rows or appends new ones.
- Nodes, setbacks, junction shapes and markers get similar small stores: `node-store.ts` and `detail-store.ts`.
- Replace direct `RoadArrays` access in the tile index, tile builder and markings with store accessors: `pointsOf(road)`, `lanes(road)` and so on. Nothing else reads `ready.roads` after load.

### `render/tiles/tile-manager.ts`: `invalidate(roadIds, nodeIds)`

1. Recompute the road bounds and the owning tile for each changed road, moving it between entries in both bands when its tile changed.
2. Mark as dirty:
   - the old and new owning tiles of each changed road
   - the owning tiles of each affected junction shape and marker
3. Destroy the dirty tiles' cached graphics. They rebuild, prioritized ahead of new tiles, within the existing 2-per-frame budget.
4. Deleted roads are skipped by the tile builder and by picking.

### `edit/picking.ts`: a uniform grid, cell 32 m

- The grid maps cells to arrays of `(road, segment index)`.
- **`pickRoad(x, y, tolerance)`:** returns the road whose segment has the smallest `distance − halfWidth`, when that is at most `tolerance`. On overlap, the higher layer wins, then the lower road id.
- **`pickNode(x, y, radius)`:** returns the nearest junction node (active degree ≥ 3) within `radius`.
- **`update(roadIds)`:** removes a road's old entries (kept per road) and adds its new ones.
- Tolerance is 6 screen px converted to metres.

### `render/selection.ts`

In `layers.overlay`:
- **Hover:** the hovered road drawn as a `#8ED8F6` stroke at alpha 0.55, with its width equal to the road width.
- **Selection:** the selected road drawn as the same stroke at alpha 0.8, plus black `#151515` node handle dots (radius 0.6 m, minimum 3 px) at its endpoints.
- Redrawn only when the hover, the selection or the road's geometry changes.

### `edit/edit-controller.ts`

- Tracks pointer-move hover, throttled to animation frames and only active when the pointer is not dragging, and click-to-select.
- **Keys:**
  - `Delete` or `Backspace` on a hovered or selected road sends `DeleteRoad`.
  - `Ctrl+Z` or `Cmd+Z` sends `Undo`.
- It shows the budget in a `.chip`, `#budget` with `data-spent`, top right.
- It shows a toast `.chip.error` for 2.5 s on an error result, with the `EditError` name mapped to a short message by a small table in `hud/messages.ts`.

### `sim/client.ts`

Adds `sendCommand(cmd)`, `quote(cmd): Promise<QuoteResult>` (keyed by `id`) and an `onCommandResults` handler.

On results, the scene updates, in this order:
1. the stores
2. `tileManager.invalidate`
3. `picking.update`
4. the selection (cleared if its road was deleted)
5. the budget chip

## Tests

- **vitest:**
  - `road-store.test.ts`: apply updates and appends, and ranges.
  - `picking.test.ts`: nearest by edge distance, layer preference, update after a geometry change, and deleted roads skipped.
  - `tile-invalidate.test.ts`, on the pure index part: a road moving tiles changes membership in both bands.
  - `protocol.test.ts` additions.
- **Playwright** (`e2e/edit-basic.spec.ts`), at `/?map=synthetic&vph=0&cx=975&cy=450&z=16`, the residential road block x = 900–1050 at y = 450:
  1. Wait for the tiles, then move the mouse to the screen centre. The hovered road is highlighted: the centre pixel is cyan-tinted, with B > R + 20.
  2. Press Delete. `#budget[data-spent]` becomes above 0, and within 2 s the centre pixel is ground colour (within ±6 of `#EEEDE6`). A road is gone.
  3. Press Ctrl+Z. Within 2 s the centre pixel is white or cyan again, and `data-spent` returns to 0.
  4. No console errors.
