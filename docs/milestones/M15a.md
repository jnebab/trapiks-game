# M15a: roundabouts

Goal: the player can replace a junction with a roundabout, and OSM roundabouts behave like roundabouts: vehicles on the ring have priority, and entering vehicles yield.

This implements the `BuildRoundabout` row of plan §3.6. It reuses M10b's append, cut, re-point and truncate machinery.

## Map format v3: the roundabout flag

- `RoadTable` gains `roundabout: Vec<bool>`. `MAP_FORMAT_VERSION` becomes 3, and `validate` checks the column length.
- **mapgen:**
  - `junction=roundabout` or `junction=circular` sets the flag. `tags.rs` already reads this tag for one-way.
  - Chain merging never merges a roundabout road with a road that is not a roundabout road.
  - **Control default:** a node with at least one roundabout road and at least one other road gets `Yield`, unless an explicit signal or stop control was assigned to it.
- `MapBuilder` gains `.roundabout(road)`, which sets the flag on a road it already added.
- Regenerate `web/public/maps/synthetic.bin.gz`.
- **`RoadStore`** gains `roundabout: Vec<bool>`.
  - `append_like` copies it, and every other append takes it as an argument.
  - `NodeStore::append(pos, control)` gains a `control` parameter. M10b's callers pass `Priority`.
- **Hashes:** `content_hash` includes the flag, so `FOUR_WAY_HASH_5000` and `GRID_CITY_HASH_1000` change. Update them, and keep the M8 native = wasm check green.
- **Renderer:** M4's `RoadGeometry` and M11a's delta `RoadRows` carry a `roundabout` column.
  - Its one consumer is the city band's `include`, which excludes flagged roads, so a ring is never drawn as a blob at city zoom.

## Ring priority and turn kinds

- **`movement_class_rank(network, road) -> u8`** returns `RING_RANK = 15` for a flagged road, which is above `Motorway` (14), and `class.rank()` otherwise.
  - `path.rs` uses it for a movement's rank.
  - So does every other place that reads the class rank for priority, including M9b's approach markers. The yield line is then drawn at the ring entries.
- **`movement_is_minor(network, node, &Movement) -> bool`** holds today's `is_minor` logic. `is_minor(network, approach)` calls it.
  - The existing `Yield` rule then makes every entry minor, because its rank is below the junction's top rank.
- **Turn kinds:** `junction.rs::candidate` sets the kind before `classify`:
  - both roads flagged: `Through`
  - exactly one flagged: `Right`
  - otherwise, `classify` as today
  - A curved ring would otherwise classify as `Left`, or even `UTurn`, which A* penalizes and lane assignment misplaces.
- **Resulting lane ranges** on a 2-lane ring:
  - ring through: `(0, 1)`
  - exit: `(0, 0)`, the outer lane
  - entry: lands in lane 0
- **`SetLanes` on a roundabout road** is rejected with `InvalidLanes` when `backward > 0` or `forward == 0`, so the ring never gets counterflow.

## `EditCommand::BuildRoundabout { node: u32, radius_m: u8 }`

### Validation (new `EditError` variants)

Checks run in M10a's order:
1. The node exists and has an active degree ≥ 3 (`NotAJunction`).
2. Region mode: every active incident road is active in the region (`OutsideRegion`).
3. `ROUNDABOUT_MIN_RADIUS = 16 ≤ radius_m ≤ ROUNDABOUT_MAX_RADIUS = 40` (`InvalidRadius`).
4. No incident active road is a roundabout road (`AlreadyRoundabout`).
5. Every active incident road, the **arms**, has both of these (`RoundaboutTooLarge`):
   - `from != to`
   - `length ≥ radius_m + 20`
6. All arms have the same layer (`LayerMismatch`).
7. Consecutive ring nodes, as placed below, are at least `ROUNDABOUT_MIN_CHORD = 8 m` apart, and their angles `θ` differ by at least 0.3 rad (`RoundaboutTooTight`). Equal angles would otherwise wrap into a full-circle ring road.

### Effect

The arms are processed in ascending road id.

1. **Cut:** for each arm `r`, cut it at distance `d = radius_m` from the node. Use M10b's cut rule, so the cut point is a vertex of the outer part.
   - Append a ring node `m_r` at the cut point, with control `Yield`.
   - Re-point `r` to its outer part. Move its endpoint at the node to `m_r` with `set_endpoint`.
   - The inner part is dropped. Its points become unreferenced, as in M10b.
2. **Ring order:** with centre `c` = the node position, sort the ring nodes by `θ = libm::atan2(y − c.y, x − c.x)` descending, with ties broken by road id.
   - World y points south (see `mapgen/src/project.rs`), so descending `θ` is counter-clockwise on screen. Right-hand traffic circulates counter-clockwise.
3. **Ring roads:** for each consecutive pair `(m_i, m_j)` in that order, cyclically, append a road `m_i → m_j`:
   - **Direction:** one-way, with `lanes_forward = ring_lanes` and `lanes_backward = 0`. `ring_lanes` is 2 when any arm has 2 or more lanes arriving at the node, and 1 otherwise.
   - **Properties:** `roundabout = true` and `speed_kph = 30`. The class is the highest class among the arms, by `rank`. The layer is the arms' layer, and the name is 0.
   - **Geometry:** an arc following the ring order.
     - `Δ = θ_i − θ_j`, wrapped into `(0, 2π]`.
     - `n = max(4, ceil(Δ · radius_m / 4))`.
     - For `k = 0..=n`:
       - `θ_k = θ_i − k·Δ/n`
       - `r_k = |m_i − c| + (k/n)·(|m_j − c| − |m_i − c|)`
       - `p_k = c + r_k·(libm::cos θ_k, libm::sin θ_k)`
     - `p_0` is set exactly to `m_i`, and `p_n` exactly to `m_j`.
4. **Append order is fixed:** first every `m_r` in arm order, then the ring roads in ring order starting from the ring node of the lowest arm id.
5. **The original node** keeps its id and control and has degree 0. Its signal cluster, if any, disappears on the rebuild. Bans at the node become inert and are kept.

### Cost and inverse

- **Cost:** `1200 + round(8 × total ring length)`.
- **Changed ids:** the node, every arm, every `m_r` and every ring road.
- **Inverse:** `UndoRoundabout { node, arms: Vec<ArmRecord>, road_len_before, node_len_before }`, where `ArmRecord { road, old_range, old_length, arrived: bool, cut: f64 }`. `arrived` is `r.to == node`, and `cut` is `d`.

### Vehicles on apply

These run before M10a's generic pass.

| Where the vehicle is | What happens |
|---|---|
| On an arm link heading toward the node, with `s ≤` new length | Stays |
| On an arm link heading toward the node, beyond the new length | Stranded |
| On an arm link heading away from the node, with `s < d` | Stranded |
| On an arm link heading away from the node, otherwise | Stays at `s − d` |

- Vehicles in movements at the node are stranded by the generic pass, because the node's movements are gone.
- Routes through the node become invalid: the arm's link now ends at `m_r`, and the old pair is not a turn there. The generic pass flags them, and M7a/M10a reroute them.

### `UndoRoundabout`, in this fixed order

This mirrors M10b's `UndoFlyover`.

0. Record `(from_link, to_link)` for vehicles in movements at the arms' far ends.
1. Strand every vehicle on a ring link or in a movement at an `m_r` node.
2. Move vehicles on arm links heading away from the node to `s + d`. Vehicles heading toward the node stay.
3. Restore each arm's range, length and endpoint (`set_endpoint(r, m_r, node)`).
4. Set `deleted = true` on the ring roads, then `version += 1`. Invalidate the junctions at the node, every `m_r` and every far end, then call `ensure_graph`.
5. With no limit, reroute every live vehicle whose `route[cursor..]` references a ring link. A failed reroute strands the vehicle.
6. Truncate roads and nodes.
7. Run M10a's generic vehicle pass on the surviving ids, with the pairs recorded in step 0.

## `sim-wasm`, protocol and UI

- `EditCommand` and the new `EditError` variants reach TypeScript through ts-rs, with no wasm API change.
- `hud/messages.ts` gets short messages for the new errors: "Radius out of range", "Already a roundabout", "Roads too short for this size", "Roads are on different levels" and "Roads too close together".
- **`node-view.ts`:** a "Roundabout" row with two action buttons, `Small` (`radius_m: 18`) and `Large` (`radius_m: 28`). They quote like every action. The tooltip reads, for example, `$2104 · Small roundabout`.
- After a roundabout is built, the re-inspected node has no junction ring, so the selection clears, as after a flyover.
- **Renderer:** ring roads render as ordinary one-way roads, with their arrows and junction shapes at each `m_r`, and yield lines at the entries. The island is the ground colour.
