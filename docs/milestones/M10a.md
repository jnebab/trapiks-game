# M10a: edit commands (framework and road/junction edits)

Goal: the sim accepts player edits as queued commands. Each edit:
- is validated,
- is costed against a budget,
- applies at the start of the next step,
- reports what it changed,
- and can be undone exactly.

Vehicles adapt: those on deleted links despawn, and routes through invalid links are rerouted within a bounded budget.

This covers every §3.6 command except `BuildFlyover` (M10b), `BuildRoundabout` and `AddRoad` (M15). `SetLayer` is removed from the plan. Layer alone never changes connectivity here, so it would be a purely cosmetic edit. Elevation arrives through flyovers and new roads.

Wasm, worker and UI plumbing are M11. M10a is `sim-core` only.

## Types (`src/edit/`, all ts-rs exported)

```rust
pub enum EditCommand {
    DeleteRoad { road: u32 },
    SetLanes { road: u32, forward: u8, backward: u8 },
    SetSpeedLimit { road: u32, kph: u8 },
    SetJunctionControl { node: u32, control: Control },
    SetSignalTiming { node: u32, greens_s: Vec<u32>, offset_s: u32 },
    SetTurnAllowed { node: u32, from_road: u32, to_road: u32, allowed: bool },
    Undo,
    SetDemand { vehicles_per_hour: f64 },
}

pub enum EditError {
    RoadNotFound, RoadDeleted, NodeNotFound, OutsideRegion, InvalidLanes,
    InvalidSpeed, NotAJunction, NotSignalized, InvalidTiming, TurnNotFound,
    NoChange, InsufficientBudget, NothingToUndo, DemandLocked, InvalidDemand,
}

pub struct EditOutcome { pub cost: i64, pub changed_roads: Vec<u32>, pub changed_nodes: Vec<u32> }
pub enum Outcome { Ok(EditOutcome), Err(EditError) }
pub struct CommandResult { pub seq: u32, pub outcome: Outcome }
```

- `Outcome` replaces `Result`, so ts-rs can export it. It serializes as `{ Ok: … } | { Err: … }`, serde's external tagging, and unit variants such as `Undo` export as string literals.
- `EditCommand` derives `Deserialize`, and the result types derive `Serialize`. `cost: i64` relies on M8's `TS_RS_LARGE_INT=number`.
- **Budget source:** `SimConfig` gains `budget: Option<i64>`. `Sim::set_budget_limit(Option<i64>)` exists for tests.
- `cost` is signed. Undo refunds give a negative cost.

## Validation rules

Checks run in this order:
1. Bounds: the id exists.
2. Deleted.
3. Region.
4. Semantic rules for the command.
5. `NoChange`.
6. Budget.

Node commands are `OutsideRegion` when the node has no active incident road.

| Command | Rules |
|---|---|
| All road commands | The road exists and is not deleted. In region mode, the road must be active in the region mask (`OutsideRegion`) |
| `SetLanes` | `forward + backward ≥ 1`, each `≤ 8` (`InvalidLanes`). Equal to the current values gives `NoChange` |
| `SetSpeedLimit` | `10 ≤ kph ≤ 120` (`InvalidSpeed`). Equal gives `NoChange` |
| `SetJunctionControl` | The node exists and has an active degree ≥ 3 (`NotAJunction`). Equal gives `NoChange` |
| `SetSignalTiming` | The node belongs to a signal cluster (`NotSignalized`). `greens_s.len()` equals the cluster's phase count, each green is 5–120 s, and the offset is below the cycle length (`InvalidTiming`). Equal to the current timing gives `NoChange` |
| `SetTurnAllowed` | The node exists. The turn `(from_road → to_road)` must be in `Network::turns(node)` computed with bans ignored (`TurnNotFound`); a U-turn at a non-dead-end is therefore `TurnNotFound`. A state already equal gives `NoChange` |
| `SetDemand` | Only in `City` mode (`DemandLocked` in region mode). The value must be finite, and `0 ≤ vph ≤ MAX_VPH = 200_000` (`InvalidDemand`). Costs 0. It is not an edit and goes on no undo stack, but it is in the command log and ordered with other queued commands |
| `Undo` | The undo stack is non-empty (`NothingToUndo`) |

## Costs (`src/edit/cost.rs`, fixed)

`len100 = max(1, round(length / 100))`, per road.

| Command | Cost |
|---|---|
| `DeleteRoad` | `50 × len100`, at least `100` |
| `SetLanes` | `+40 × len100` per added lane, `+10 × len100` per removed lane, and `+50` extra when the road switches between one-way and two-way |
| `SetSpeedLimit` | `10` |
| `SetJunctionControl` | `Signal` 500. `AllWayStop` 80. `Stop` 50. `Yield` 30. `Priority` 50, which is what removing a control costs |
| `SetSignalTiming` | `20` |
| `SetTurnAllowed` | `20` |

Every cost is computed from the pre-edit state.

**Budget:** `Budget { limit: Option<i64>, spent: i64 }`. A command whose cost would push `spent` above `limit` fails with `InsufficientBudget`. `Undo` refunds exactly the cost of the edit it reverts.

**Quoting:** `Sim::quote(&Command) -> Result<i64, EditError>` validates and prices without applying. The UI uses it for tooltips.

## Applying edits (`src/edit/apply.rs`)

Each command maps to an internal `Edit`. Applying an `Edit` returns its inverse `Edit`, plus the changed roads and nodes.
- `Undo` applies the stored inverse, LIFO only, without validation or budget checks, and does not push a new undo entry.
- `Timing { green_ticks: Vec<u32>, offset_ticks: u32 }`, where the greens are converted from seconds × 10.

| Edit | Effect | Inverse |
|---|---|---|
| `SetDeleted { road, deleted }` | Sets the flag | Opposite flag |
| `SetLanes` | Stores the new counts | Old counts |
| `SetSpeed` | Stores the new speed | Old speed |
| `SetControl` | Stores the new control | Old control |
| `SetTiming { key: u32, timing: Option<Timing> }` | Stores or removes the override for `key` (`None` removes it) | The previous `Option<Timing>` |
| `SetBan` | Inserts into or removes from `bans` | Opposite |

After any edit:
1. Invalidate the junctions at the endpoints of every changed road, and at every changed node. `SetSpeed` skips this, because no junction data depends on speed.
2. Rebuild `Signals` when a control or timing edit happened, or when a road incident to a signalized node changed.
3. `version += 1`.

The route graph, demand tables and `LinkCosts` (`free_speed`, `drive_len`, and the tables' size) rebuild through the existing version check.

- **`LinkCosts` rebuild:** keeps each link's EMA when its road still exists and has lanes in that direction, clamped with `ema = min(ema, free_speed)`. Otherwise it resets to `free_speed`. The per-link sample window is cleared.
- **Signal timing storage:** the network stores per-cluster timing overrides as `BTreeMap<u32, Timing>`, keyed by the smallest node of the cluster.
  - `Signals::build` is pure: it applies an entry only when both the key and the phase count match, and it never removes entries.
  - Only `SetTiming` and its inverse mutate the map. LIFO undo is then exact, and an orphaned override applies again if a later edit restores its cluster.
- **Queued trips:** trips already in `LinkQueues` or `trip_queue` whose origin or destination becomes inactive fall out as unserved through M7b's existing error paths.
- **Region mask:** its boundary, source and sink lists are not rebuilt after edits. That is accepted; do not add machinery for it.
- **Speed storage:** `RoadStore` gains `speed_kph: Vec<u8>`. `speed` stays derived from it. `NoChange` and `content_hash` use the `u8`.

**`Network::content_hash() -> u64`:** FNV over every road's `(deleted, lanes, speed_kph, layer, from, to)`, the node controls, the bans in order, and the timing overrides in key order.
- It is cached by `version`.
- Tests use it, and `state_hash` also includes it.

## Vehicles after an edit (`src/edit/vehicles.rs`)

1. **Deleted or zero-lane links:** vehicles on a link that no longer exists despawn and count as `stranded`.
2. **Lane clamp:** vehicles on a link whose lane count dropped get `lane = min(lane, lanes − 1)`.
3. **Movement remap,** at apply time:
   - Before invalidating a node, record `(from_link, to_link)` for every vehicle in a movement there.
   - After the invalidation, call `ensure_junction` at each such node, then re-find each vehicle's movement index by its pair.
   - A vehicle whose movement no longer exists despawns as `stranded`.
   - Clamp `from_lane` and `to_lane` to the lane counts, and clamp `s = min(s, new movement length)`.
4. **Flagging,** done in one pass:
   - Build `affected_links: BTreeSet<LinkId>`, holding both links of every changed road.
   - For each changed node, call `Network::turns(node)` once to get its set of valid `(from, to)` pairs.
   - For each live vehicle, scan `route[cursor+1..]`. It is flagged when a link is in `affected_links` and now inactive, or when a pair whose via-node is a changed node is no longer valid.
   - The result is `flagged: BTreeSet<u32 /*slot*/>`. Releasing a slot removes it from `flagged`, and so does an M7a step-1 reroute of that slot.
   - Each step reroutes at most `FLAGGED_REROUTE_BUDGET = 4` flagged vehicles, in slot order, using M7a's reroute routine. This pass runs after M7b's step 2 and before trip routing, so the "4 + 4" route-work invariant holds. Update plan §3.5 item 2 to read "slot order".
   - M7a's unlimited step-1 reroute still catches any vehicle that reaches the broken part first.
5. **Committed vehicles:** clear `committed`, and only `committed`, on every vehicle on a link arriving at an invalidated node. M6's predecessor rule (a committed vehicle never sits behind an uncommitted one) keeps holding.

## Queue and step order

- `Sim::enqueue(cmd) -> u32` returns a sequence number. Commands wait in a `VecDeque`.
- At the start of `step`, before M7b's step 1, every queued command is applied in order.
- `Sim::take_results() -> Vec<CommandResult>` drains the results.
- `state_hash` covers:
  - the undo stack entries (each inverse edit's fields and cost)
  - `budget.spent`
  - `content_hash()`
  - the flagged slots, in order
  - the queued command count

## Tests

1. **`edit_roundtrip`:**
   - For each edit kind on `grid_city(10×10 @ 150)`: record `content_hash`, apply, step, `Undo`, step.
   - `content_hash` must equal the original.
   - The budget must return to its original `spent`.
   - The results must report the same changed ids in both directions.
2. **`edit_rejections`:** every `EditError` variant is produced by a concrete command.
3. **`delete_road_vehicles`:** on `corridor()`, delete road 1 while vehicles are on it.
   - Those vehicles despawn as stranded.
   - Vehicles behind them, on road 0 routed through road 1, are flagged and rerouted or stranded.
   - Invariants from M6 hold.
4. **`lanes_edit_clamps`:** reduce a 2-lane approach at `four_way` to 1 lane with vehicles on lane 1. They move to lane 0 without NaN, and M6 invariants hold within 50 ticks.
5. **`control_edit`:**
   - Set `Signal` on a `t_junction` node. A cluster appears, and the minor approach now waits for its phase.
   - Undo restores `Priority`.
6. **`timing_edit`:** `SetSignalTiming` on `four_way` with `[5, 5]` gives a new cycle of 200 ticks, `(50 + 30 + 20) × 2`, and the phase boundaries move accordingly. Undo restores the 700-tick cycle and removes the override.
7. **`turn_ban_edit`:** ban a left turn at `four_way`. Vehicles already routed through it are flagged and rerouted within `ceil(flagged / 4)` steps.
8. **`budget`:** with a limit of 150, `DeleteRoad` succeeds (100), a second `DeleteRoad` fails with `InsufficientBudget`, and `Undo` refunds.
9. **`determinism_with_edits`:** `grid_city(20×20 @ 150)` at 8,000 vph, enqueuing a fixed list of 6 edits at ticks 100, 200, … 600. Two runs give equal hashes and equal drained `CommandResult` lists.

## Bench

`examples/bench.rs` gains `--delete-road-at <tick>`. It deletes the most-used primary road (the one with the most vehicles at that tick), then reports the max step time over the next 600 ticks.

Run it on `120x120@150` at `--vph 100000` with a warmup of 9,000. The target is a max step ≤ 50 ms native.
- A tie for "most-used road" goes to the lowest id.
- At the delete tick, print the stranded, immediate-reroute and flagged counts.
- If the target is missed, the known risks and their fallbacks are:
  - **Full route graph and signals rebuild per edit:** patch only the CSR successor lists of changed nodes, and rebuild only the affected clusters.
  - **Too many immediate step-1 reroutes:** only vehicles inside their decision zone reroute immediately; the rest are flagged.
- Report which fallback, if any, was needed, and don't implement one without the orchestrator.
