# M3: network runtime

Goal: `trapiks-sim-core` turns a `MapData` into a runtime `Network`:
- directed links with lanes and junction setbacks
- lazily built junctions: movements, lane ranges, Bézier paths, conflict points and priority ranks
- signal clusters with phase plans
- a spatial grid
- a region mask for challenges

## Network stores (`src/network/`)

### `road.rs`: `RoadStore`

- It is built from `MapData`. Its fields are:
  - `from`, `to`, `class`, `lanes_forward`, `lanes_backward`, `layer`, `name`
  - `speed: Vec<f64>` in m/s, where kph ÷ 3.6
  - `deleted: Vec<bool>`, all false at load
  - `point_start`, `points: Vec<Vec2>` (map f32 widened to f64) and `cumulative: Vec<f64>`, aligned with `points` and restarting at 0 for each road
  - `length: Vec<f64>`
- Accessors:
  - `count()`, `points(road) -> &[Vec2]`, `cumulative(road) -> &[f64]`
  - `total_lanes(road) -> u8`
  - `width(road) -> f64` = total lanes × `LANE_WIDTH`
  - `is_live(road) -> bool`, which is `!deleted`

### `node.rs`: `NodeStore`

- Fields: `pos: Vec<Vec2>`, `control: Vec<Control>`, and `roads: Vec<Vec<u32>>`, the incident road ids in ascending order, including deleted roads.
- Callers filter by liveness.

### `link.rs`

- `pub type LinkId = u32`, and `pub enum Direction { Forward = 0, Backward = 1 }`.
- `link_id(road, dir) = road · 2 + dir`, `road_of(link) = link / 2`, `direction_of(link)` and `reverse(link) = link ^ 1`.
- There is no stored link table. Links are derived from `RoadStore`:
  - A link's lanes are the lane count in its direction; 0 means it does not exist.
  - Its from node is the road's `from` for `Forward`, and `to` for `Backward`.
- Link coordinates run from 0 to `length` in the direction of travel. For `Backward`, `s_road = length − s_link` and the tangent is negated.

### `setback.rs`

`pub fn setback(roads, nodes, is_active, node, road) -> f64`:
- The degree of `node` is its number of incident active roads.
- **Degree 1** (a dead end): 0.
- **Degree 2:** `min(LANE_WIDTH, MAX_SETBACK_FRACTION × length(road))`. This keeps a movement's end at least 6.4 m ahead of its start, so the Bézier never folds back.
- **Degree 3 or more:** the largest `width / 2` over the node's other active incident roads, plus `SETBACK_MARGIN`, capped at `MAX_SETBACK_FRACTION × length(road)`.
- The 7.4 m value in the tests is unaffected.

## `spatial.rs`: `SpatialGrid`

- Uses a uniform grid of `SPATIAL_CELL` metres over the bbox of every road point and node, expanded by one cell.
- Storage is CSR: `cell_start: Vec<u32>` plus `ids: Vec<u32>`, built with a counting pass. There is one table for roads and one for nodes.
- **Registration:**
  - Each road is registered in every cell overlapped by the bbox of each of its segments. Deduplicate per cell by checking the last pushed id.
  - Each node is registered in its cell.
- **Queries:**
  - `roads_in_rect(min, max) -> Vec<u32>`, sorted and deduplicated.
  - `nodes_within(center, radius) -> Vec<u32>`, sorted, using exact distance.
  - `roads_near(center, radius) -> Vec<u32>`: roads with at least one point within `radius`, sorted.
  - This tests points, not segments. A long 2-point road crossing a circle can be missed; this is accepted.

## `junction.rs`

```rust
pub enum TurnKind { Right, Through, Left, UTurn }
pub struct Movement {
    pub from_link: LinkId,
    pub to_link: LinkId,
    pub kind: TurnKind,
    pub from_lanes: (u8, u8),
    pub primary_lanes: (u8, u8),
    pub path: [Vec2; BEZIER_SEGMENTS + 1],
    pub cumulative: [f64; BEZIER_SEGMENTS + 1],
    pub length: f64,
    pub rank: (u8, u8),
}
pub struct Conflict { pub other: u16, pub s_self: f64, pub s_other: f64, pub merge: bool }
pub struct Junction { pub node: u32, pub movements: Vec<Movement>, pub conflicts: Vec<Vec<Conflict>> }
```

`TurnKind::rank()`: `Through` = 3, `Right` = 2, `Left` = 1, `UTurn` = 0.

### `build_junction(network, node) -> Junction`

1. **Links:** incoming links are the active links whose to-node is `node`; outgoing links are the active links whose from-node is `node`. Both are sorted by id.
2. **Candidate movements:** every `(a, b)` pair of incoming link `a` and outgoing link `b`.
   - If `b == reverse(a)`, keep it only when the node's active degree is 1 (a dead end).
   - Drop it when `TurnBan { via_node: node, from_road: road_of(a), to_road: road_of(b) }` is banned.
3. **Tangents:** `d0` is the centreline tangent of `a` at `s = length − setback(to-node of a)`, and `d3` is the centreline tangent of `b` at `s = setback(from-node of b)`. Tangents are lane-independent.
4. **Turn kind:**
   - `b == reverse(a)` gives `UTurn`.
   - Otherwise, let `θ = signed_turn(d0, d3)`. `|θ| ≤ 30°` gives `Through`. `|θ| ≥ 150°` gives `UTurn`. Otherwise `θ > 0` gives `Right` and `θ < 0` gives `Left`.
5. **Lane ranges**, per incoming link `a` with `F` lanes, over its kept movements:
   - `F == 1`: every movement gets `(0, 0)`.
   - With a through movement: `Through` gets `(0, F−1)`, `Right` gets `(0, 0)`, and `Left`/`UTurn` get `(F−1, F−1)`.
   - Without a through movement but with both rights and lefts/U-turns: rights get `(0, F/2 − 1)` and lefts/U-turns get `(F/2, F−1)`.
   - Rights only, or lefts/U-turns only: `(0, F−1)`.
6. **Primary lanes:**
   - `Right`: `(from_lanes.0, 0)`.
   - `Left` and `UTurn`: `(from_lanes.1, N−1)`, where `N` is the lane count of `b`.
   - `Through`: `(0, 0)`.
7. **Path:**
   - `P0` is the end point of `a` at that `s`, offset by lane `primary_lanes.0`.
   - `P3` is the start point of `b` at that `s`, offset by lane `primary_lanes.1`.
   - Lane offset: `lane_offset(road, lane) = width(road)/2 − (lane + 0.5) · LANE_WIDTH`, along `perp_right` of the link tangent.
   - `h = 0.4 · |P3 − P0|`, and for `UTurn`, `h = max(h, 2 · LANE_WIDTH)`.
   - The Bézier is `P0, P0 + d0·h, P3 − d3·h, P3`, sampled into `BEZIER_SEGMENTS` segments, with cumulative lengths and total length.
8. **Rank:** `(class(road_of(a)).rank(), kind.rank())`.
9. **Order:** movements are sorted by `(from_link, to_link)`, and `movement_index(from, to) -> Option<usize>` uses binary search.
10. **Conflicts**, for each pair `i < j`:
    - Same `from_link`: no conflict.
    - Same `to_link`: a merge conflict at `(length_i, length_j)`.
    - Otherwise: the first intersection of their sampled paths, visiting segments of `i` in order, then segments of `j`. The smallest `s_i` wins, and ties go to the smallest `s_j`. That gives a crossing conflict at `(s_i, s_j)`.
    - Skip a pair without testing segments when the bboxes of its sampled paths are disjoint.
    - Each conflict is stored in both lists with `s_self` and `s_other` swapped.
    - Each list is sorted with `f64::total_cmp` on `s_self`, then by `other`.

## `signal.rs`

```rust
pub enum SignalState { Green, Amber, Red }
pub struct SignalCluster {
    pub nodes: Vec<u32>,
    pub approaches: Vec<LinkId>,
    pub phases: Vec<Vec<LinkId>>,
    pub green_ticks: Vec<u32>,
    pub offset_ticks: u32,
}
pub struct Signals { ... }
```

### Build

- The signature is `Signals::build(roads, nodes, spatial, is_active: impl Fn(u32) -> bool)`. It takes the stores directly, not `&Network`.

1. **Signalized nodes:** nodes with `Control::Signal` and an active degree of at least 3. Signals at nodes with degree 2 or less are ignored.
2. **Clustering:** union-find over signalized nodes. Two nodes join when their straight-line distance is at most `SIGNAL_CLUSTER_RADIUS`, found with `nodes_within`. Clusters are ordered by their smallest node id, and each cluster's nodes are sorted.
3. **Link types:**
   - Internal links have both endpoints in the cluster.
   - Approaches are active links whose to-node is in the cluster and whose from-node is not. They are sorted by id.
4. **Phases:**
   - Let `a0 = axis_angle` of the first approach's tangent at its end.
   - For each approach: `d = |a − a0| mod π`, then `δ = min(d, π − d)`, which lies in `[0°, 90°]`. `δ ≤ 35°` puts it in bin A; `δ ≥ 55°` puts it in bin B; anything else is unbinnable.
   - When every approach is binned and both bins are non-empty, the phases are `[A, B]`.
   - Otherwise there is one phase per approach, in id order.
5. **Timing:** every phase gets `SIGNAL_GREEN_TICKS`, and the offset is 0.

### Queries

- **`state(link, tick) -> Option<SignalState>`:**
  - Returns `None` for links that are not approaches, including internal links.
  - Otherwise `t = (tick + offset) mod cycle`, where `cycle = Σ(green + AMBER + ALL_RED)`. Walking the phases in order, the link's own phase gives `Green` during its green window and `Amber` during its amber window. Every other window, including all-red, gives `Red`.
  - Windows are half-open: green is `[start, start + green)`, amber is `[start + green, start + green + amber)`, and all-red follows.
- `cluster_of(node) -> Option<u32>`, `is_internal(link) -> bool` and `clusters() -> &[SignalCluster]`.

## `region.rs`

- `pub struct Region { pub center: Vec2, pub radius: f64 }`.
- `RegionMask::build(network, region)`:
  - `active_road[r]` is true when road `r` is live and `roads_near(center, radius)` contains it.
  - `boundary` holds the nodes incident to at least one active road and at least one inactive live road, sorted.
  - `sources` are the active links whose from-node is a boundary node, and `sinks` are the active links whose to-node is a boundary node. Both are sorted.

## Example

`crates/sim-core/examples/build_junctions.rs` (with `flate2` as a dev-dependency):
- It takes the path of a `.bin.gz` map, gunzips it, calls `from_bytes` and `Network::from_map`, then times `build_all_junctions`.
- It prints: nodes, live roads, junctions built, total movements, total conflicts, signal clusters, and milliseconds.
- It also prints an estimated byte total: `movements × size_of::<Movement>() + conflicts × size_of::<Conflict>()`.
- Run it on `web/public/maps/synthetic.bin.gz`.
